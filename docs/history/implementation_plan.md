# 실어증 하위검사(QAB) 어플리케이션 구현 계획

본 문서는 실어증 회복 연구 대상인 Quick Aphasia Battery (QAB)의 8가지 하위 검사를 모바일/웹 어플리케이션으로 구현하기 위한 기획 및 기술적 구현 계획(Implementation Plan)입니다.

## User Review Required

> [!IMPORTANT]
> 본 기획안에 대해 다음 사항들의 검토가 필요합니다:
> 1. 타겟 플랫폼(웹, iOS, Android 등) 확정 여부
> 2. 음성 인식(STT) 및 평가에 사용할 AI 모델(예: Whisper, Google STT, 자체 모델 등) 선정
> 3. 임상 데이터의 보안 및 개인정보 보관 규정(HIPAA 등) 준수 여부 및 백엔드 연동 방안

## 기능 정의 및 하위검사별 구현 계획 (Proposed Changes)

어플리케이션은 환자가 독립적으로 또는 보호자/치료사의 보조 하에 검사를 수행할 수 있도록 설계됩니다.

### 1. 의식 수준 (Level of Consciousness)
- **평가 목적:** 환자의 각성 상태 및 검사 참여 가능 여부 평가
- **UI/UX 기획:** 
  - 화면에 "여기를 눌러주세요"와 같은 직관적인 큰 버튼 또는 심플한 터치 상호작용 화면 제공.
  - 음성 안내를 통해 지시사항 전달.
- **기술적 구현:** 
  - 버튼 터치 반응 속도 및 정확성 측정 기능.
  - 지시 후 반응까지의 지연 시간(Latency) 로깅 알고리즘 적용.

### 2. 연결 발화 (Connected Speech)
- **평가 목적:** 자발적 대화 상황의 유창성, 운율, 문법 능력 평가
- **UI/UX 기획:** 
  - 특정 상황(예: 소풍 장면, 가족 사진 등)의 고해상도 그림 제시.
  - 직관적인 음성 녹음 시작/종료 버튼 (애니메이션이 포함된 마이크 아이콘).
- **기술적 구현:** 
  - 기기 마이크를 통한 기기 내 음성 녹음 및 스트리밍.
  - STT(Speech-to-Text) API 연동을 통해 분당 단어 수(WPM) 자동 계산.
  - 언어 모델(LLM)을 활용한 문장 구조 및 착어증(Paraphasia) 1차 자동 분석 로직 구현.

### 3. 단어 이해 (Word Comprehension)
- **평가 목적:** 청각적 단어 인지 능력 평가
- **UI/UX 기획:** 
  - 1개의 목표 단어 음성 반복 재생 버튼 + 3~4개의 혼동하기 쉬운 이미지 화면 분할 제시.
  - 오답/정답 선택 시 시각적 채점 피드백 (환자의 스트레스 고려하여 선택적 표시).
- **기술적 구현:** 
  - 오디오 에셋 동기화 재생 로직.
  - 터치 이벤트 기반 정답 여부 실시간 판별 및 반응 시간(ms 단위) 기록.

### 4. 문장 이해 (Sentence Comprehension)
- **평가 목적:** 복잡한 구문론적 문장 이해력 평가
- **UI/UX 기획:** 
  - 복잡한 구문(예: 수동태 구문)의 문장 음성 재생.
  - 문장이 묘사하는 정답 그림과 거리가 먼 오답 그림들을 함께 제시하여 선택 유도.
- **기술적 구현:** 
  - 그림 선택 시 로깅 및 정답률 산출 모듈 확립.

### 5. 그림 이름대기 (Picture Naming)
- **평가 목적:** 어휘 인출 및 음운 산출 능력 평가
- **UI/UX 기획:** 
  - 단일 사물/인물 그림을 화면 중앙에 크게 제시.
  - 그림이 나오는 즉시 음성 녹음 대기 상태 진입.
- **기술적 구현:** 
  - 음성 인식 VAD(Voice Activity Detection) 센싱을 통해 발화 시작 타이밍 정밀 측정.
  - STT를 통해 음운 착어 vs 의미 착어 분류 알고리즘 구축 (정답 단어와의 Levenshtein 거리 계산 등을 활용한 유사도 판단).

### 6. 따라말하기 (Repetition)
- **평가 목적:** 음운 부호화 및 청각-운동 통합 능력 평가
- **UI/UX 기획:** 
  - 단어/문장 음성 재생 및 후행 녹음 가이드 (시각적 타이머 표시).
- **기술적 구현:** 
  - 원본 음성 대본의 텍스트와 STT 변환 텍스트 간 정확도 비교.
  - 추가적으로 음향적 특징을 비교하는 보조 알고리즘 도입 검토.

### 7. 소리 내어 읽기 (Reading Aloud)
- **평가 목적:** 자소-음소 변환 및 시각적 언어 처리 평가
- **UI/UX 기획:** 
  - 가독성 높은 큰 텍스트 렌더링.
  - 화면 전환과 동시에 타이머와 녹음을 시작.
- **기술적 구현:** 
  - 화면 표시 시간부터 실제 첫 발화 시작 시간까지의 지연 여부 측정.

### 8. 말운동 프로그래밍 (Motor Speech)
- **평가 목적:** 구어 산출을 위한 운동 계획 및 실행 능력 평가 (언어장애와 구어장애 감별)
- **UI/UX 기획:** 
  - 모범적인 입모양 비디오나 3D 애니메이션 모델 제시 (예: "파-타-카" 교대운동 시연 등).
- **기술적 구현:** 
  - 오디오 주파수 및 포먼트(Formant) 분석을 위한 오디오 시그널 처리 로직 (Python 기반의 Librosa 또는 파생 API) 활용.
  - 조음의 속도 및 패턴의 규칙성 분석.

## Verification Plan

### Automated Tests
- **단위 테스트 (Unit Tests)**: 
  - STT 결과를 입력받아 WPM, 문법 에러, 단어 유사도(Levenshtein)를 정상적으로 채점하는지 스크립트 기반 테스트 (예: `pytest tests/test_scoring.py`).
- **UI 인터랙션 검증**: 
  - 웹 환경일 시 `Cypress`, 모바일일 시 `Appium` 등을 통해 가상사용자가 모든 하위 검사의 버튼과 이미지를 시간 지연 없이 클릭/진행할 수 있는지 e2e 테스트.

### Manual Verification
- **디바이스 기능 확인**: 개발용 에뮬레이터 및 실제 기기에 배포하여 마이크/스피커 권한 요청, 정상 작동, 레이턴시 여부 수동 점검.
- **환자 및 언어치료사 시뮬레이션**: 전문가가 QAB 프로토콜 원본 지침서와 동일한 템포와 방식으로 앱 구성이 적절한지 직접 모의 검사 수행하여 피드백 수집.
