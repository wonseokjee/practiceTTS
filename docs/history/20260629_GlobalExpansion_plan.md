## 2. 웰니스 포지셔닝의 함의

### 가벼워지는 부분
- **임상 콘텐츠**: QAB 등 검증 진단 도구의 규준(norm) 재산출 불필요. "두뇌 건강 훈련 / 인지 웰니스 운동"으로 재프레이밍 → 언어적으로 자연스러운 콘텐츠면 충분 (SLP 규준 연구 없이 시작).
- **규제**: FDA SaMD, CE-MDR 인증 트랙 회피 → 출시 속도 ↑.

### 여전히 필요한 부분
- 개인정보 보호는 면제 안 됨 (아래 미국 컴플라이언스 참조).
- **마케팅 문구 가드레일** (FTC Act상 법적 요구사항이기도 함):

| ❌ 의료기기로 분류될 표현 | ✅ 웰니스 허용 표현 |
|---|---|
| 실어증 **진단** / **치료** | 두뇌 건강 **훈련** |
| 인지 저하 **검사** / **평가** | 기억력 **활동** / **운동** |
| 회복 (의학적 회복 주장) | 꾸준한 두뇌 자극 |

→ 현재 코드의 "검사(Assessment)", "QAB", "회복" 용어가 UI·문서에 산재. **해외 버전 문구는 웰니스 어휘로 매핑** (i18n 키 작업과 통합).

### "나중에 확장"을 막지 않기 위해 지금 지킬 것
1. **데이터 스키마는 임상 등급으로 유지** — 점수·응답·타임스탬프 충실 기록(미래 임상 검증 데이터로 활용). 현재 구조 유지만 하면 됨.
2. **콘텐츠와 "검사 도구"를 코드상 분리** — 웰니스 문항 세트와 미래의 검증된 검사 세트를 같은 엔진이 다루도록 추상화. 현재 `assessments` / `quiz` 분리 구조가 유리.
3. **포지셔닝은 마케팅/i18n 레이어에서 토글** — 의료 주장 여부를 코어 로직이 아닌 상위 레이어에서 제어.

## 3. 미국 시장 기준 확정 사항

| 항목 | 결정 |
|---|---|
| 1차 i18n 언어 | `en-US` 단일 시작 |
| 개인정보법 | **HIPAA 대상 아님** (D2C 웰니스 앱은 적용 제외). **CCPA/CPRA**(캘리포니아) + **FTC Health Breach Notification Rule** 준수 |
| 마케팅 규제 | **FTC Act** — 허위·과장 건강 주장 금지 (웰니스 어휘 가드레일이 곧 법적 요구사항) |
| TTS 음성 | Azure `en-US` Neural (따뜻한 톤 선정) |
| 인프라 | Azure US 리전. EU만큼 엄격한 데이터 레지던시 없음 → 멀티리전 부담 ↓ |
| 결제 | Stripe USD + **Stripe Tax** (주별 sales tax 자동 처리) |
| 접근성 | **WCAG 2.1 AA** — 고령 사용자 대상, ADA 분쟁 예방 |

> 미국은 사실상 다국어 국가. **스페인어(`es-US`)가 가장 강력한 fast-follow**. i18n 구조를 처음부터 2개 언어 가정으로 설계하면 추가 비용 최소화.

## 4. 실행 로드맵

### Phase 0 — 기반 (시장 무관, 선투자)
- `react-i18next` 도입 + 전체 UI 문자열 키 추출 (`ko` 기본 + `en` 추가)
- `tts_cache`에 `locale` / `voice` 컬럼 추가, 사전생성(pregenerated) 파이프라인 언어별 분기
- 용어 매핑 레이어: "검사/QAB/회복" → 영어판 웰니스 어휘

### Phase 1 — 영어 콘텐츠
- LangChain 프롬프트 영어판 + 퀴즈/문장 생성 품질 영어 검증
- 웰니스 문항 세트 영어 작성 (임상 규준 불필요, 언어적 자연스러움만)
- 데이터 스키마 임상 등급 유지 (미래 의료기기 확장 대비)

### Phase 2 — 컴플라이언스 & 출시 인프라
- CCPA 데이터 권리(열람·삭제·옵트아웃), 동의 플로우
- 개인정보처리방침/이용약관 영문 (FTC 가드레일 반영)
- Stripe USD + Tax, Azure US 리전 배포
- WCAG 2.1 AA 접근성 점검
