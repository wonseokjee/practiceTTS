## Problem

앱의 차별점은 **환자와 보호자 두 사람의 회복을 모두 추구하는 것**이다(사용자, 2026-10-04). 지금 보호자 쪽은
일기와 환자 점수 화면뿐이라 보호자 자신(감정·삶)은 다루지 않는다. 창업자는 치료사가 아니므로 사람이
피드백·개입하는 방식은 쓰지 않는다.

## 근거 (요약)

- 비전문가 전달로도 우울이 나아짐: COBRA(행동활성화=인지행동치료 비열등), Friendship Bench(일반인 문제해결,
  우울 14% vs 50%), WHO Step-by-Step(일반인 주 15분, d=0.73). 공통점 = 단순한 구조 + 일반인 전달.
- 선배 멘토링: 구조 있는 경험자 1:1은 효과, 단순 말벗은 무효(BECCA·SHIELD). 실어증 SUPERB — 짝꿍 측도 보람.
- 생성형 AI: Therabot RCT(4주 우울 감소) — 단 전문가가 쓴 대화로 학습·연구진 감독. AI 저작 공개 시 진정성 하락.
- 운동: 걷기 g=0.62(BMJ 2024). 혼자 하는 인터넷 CBT는 가벼운 우울에서 안내형과 거의 같음.

## 결정된 전제

1. 두 사람의 회복 모두가 목표. 함께 보여줄 땐 **해낸 일(사실)만 나란히**, 점수·기분은 각자 화면.
2. **가짜 선배 페르소나 금지.** 정체(도우미·AI 사용 시 AI임)를 처음부터 밝히고, 실제 선배 보호자 이야기(동의·출처 표시)를 **원문 그대로** 쓴다.
3. **역할: 치료가 아니다.** 대화 카드 4단계(힘든 일 하나 → 바꿀 수 있나 → 선배들은 → 이번 주 작은 일, 예: 걷기).
4. **순서(외부 의견 수용, C 결정 대체):** Phase 0 인터뷰 → Phase 1 LLM 없는 카드 흐름 출시 → Phase 2 사용률·이탈을 본 뒤 생성형 대화.

## 단계별 범위

### Phase 0 — 선배 보호자 인터뷰 (선행, 코드 0)
- 카페·자조모임에서 선배 보호자 5~10명. 동의서(이야기 사용·익명화·출처 라벨), 상황별 이야기 조각 30~60개.
- 이야기 검수자(임상 자문 또는 경험 많은 보호자)를 정한다.

### Phase 1 — 카드 흐름 (LLM 없음)
| # | 구성 | 내용 |
|---|---|---|
| P1-1 | 이야기 저장소 | 이야기 조각을 DB에 원문·출처 라벨·상황 태그로 보관(공개 저장소에 넣지 않음) |
| P1-2 | 카드 흐름 화면 | 4단계 정해진 화면. 1단계 "힘든 일"은 선택지 + 선택 자유 입력, 3단계는 태그로 고른 이야기 원문 + 출처 칩 |
| P1-3 | 위기 경로 | 자유 입력에 위기 규칙(자해/타해(환자)/학대 3분류). 걸리면 분류별 사람이 쓴 고정 문구 + 연결처(109, 112·119, 노인보호전문기관 등 — 연결처 확인 필요) |
| P1-4 | 작은 일 기억 | 보호자가 고른 "이번 주 작은 일" 한 줄만 계속 보관(암호화), 다음 주 첫 화면에서 확인 |
| P1-5 | 자유 입력 원문 | 14일 암호화 보관 + 매일 자동 삭제 + 보호자 즉시 삭제 |
| P1-6 | 진입점 | 일기 '나의 하루' 단계 끝 이어가기 + 보호자 대시보드 고정 카드. 새 탭 없음 |
| P1-7 | 동의·고지 | 첫 진입 때 민감정보 별도 동의 + "치료 아님·위기 시 연결처·운영자는 개입하지 않음" 고지 |
| P1-8 | 켜고 끄기 | 서버 즉시 끄기 스위치("잠시 쉬어요 + 109") + 허용 계정 목록 단계 공개 |
| P1-9 | 로케일 | 한국어만. 영어는 도우미용 별도 게이트로 닫아둠(T7·SB 243·일리노이 확인 후) |

### Phase 2 — 생성형 대화 (진입 조건 충족 후)
진입 조건(외부 의견 기록, 2026-10-04):
- Phase 1 실제 사용률·이탈 데이터가 생성 대화의 필요를 보여줄 것.
- **이야기 원문 고정**: 모델은 이야기 ID 선택과 연결 문장만, 원문은 DB 그대로 표시. 목록에 없는 ID는 코드에서 거절(외부 2).
- **평가 세트를 외부 출처로**(자살예방 교육 자료의 우회 표현 등), 모델 감지기 실패 시 fail-closed 명시, 놓친 비율은 0 주장 대신 측정·공개(외부 4).
- **Gemini `safety_settings` 명시** + 필터 차단과 위기를 구분(필터 차단은 "다시 말해볼까요"), 오탐률 상한을 배포 관문에(외부 5).
- **공유 `gemini_client` 오류 분리(결정 9)를 먼저**: 지금 `complete()`는 차단 시 `response.text`(None)를 예외 없이 반환.
- **상한은 새 종류 `caregiver_chat`**(가구·전체 상한, 마이그레이션 CHECK)으로, 위기 검사 뒤 서비스 계층에서 `consume` 호출 — `DailyCapGuard`는 핸들러 전에 돌아 쓸 수 없고 환자 `conversation` 할당량과 섞이면 안 됨(외부 6, 코드 확인).
- **저장 계층은 새로 만드는 작업**으로 추정(`chat_service`는 프로세스 메모리) — 요약 저장 없음(외부 7·8).
- **Gemini 유료 계약(학습 미사용) 확인이 관문** — 무료 티어면 시작하지 않는다. 실명 가리기는 등록 가족 이름 토큰화 + 로컬 단계, 방어선은 동의·계약(외부 9).
- 검색(RAG)은 이야기 150개 초과 시.

## 이미 있는 것

- 환자 모드 잠금(`App.tsx` `CaregiverRoute`, `ReturnToCaregiverPinModal`) — 공유 기기 보호에 재사용.
- 발화 동의 화면(`SpeechConsentScreen`) 패턴 — 도우미 동의에 재사용.
- `CryptoService` 암호화, 오류 코드 계약(`common/error-codes.ts`), i18n.
- 일기 3-step 흐름(`MyDayStep` 등) — 진입점.
- (Phase 2) `gemini_client`, `chat_service`(메모리 세션 — 재사용 어려움), 마스킹 로컬 단계, 페르소나 토큰화, `DailyCapGuard`·전체 상한(가드 구조라 그대로는 못 씀).

## NOT in scope (이번 리뷰)

- 생성형 자유 대화 — Phase 2(진입 조건 충족 후).
- 실제 사람 선배 짝꿍 매칭 — 후속(이야기 저장소·인터뷰 대상이 후보 풀이 됨).
- 영어판 도우미 — 법률 확인 후 별도 게이트로.
- 컨텍스트 캐싱 등 비용 최적화 — Phase 2.
- 보호자 자가점검(PHQ-2 등) — 별도 결정(임상 자문 필요).

## Dream state delta

12개월 이상형("두 사람의 한 주" 루프 + 보호자 코치 + 사람 짝꿍 출구 + 유료 층 핵심 가치) 대비, 이 계획은
**뼈대(카드 흐름·실제 이야기·위기 경로·동의·끄기 스위치)를 먼저 깐다.** 생성 대화와 짝꿍은 그 위에 얹는다.

## 흐름 (Phase 1)

```
 [일기 '나의 하루' 끝 / 대시보드 카드]
        │ (보호자 라우트 — 환자 모드면 막힘)
        ▼
 [첫 진입: 고지(치료 아님·위기 시 연결처·운영자 비개입) + 민감정보 별도 동의] ──거절──▶ 돌아가기
        │동의
        ▼
 [① 힘든 일 하나: 선택지 + 선택 자유 입력] ──자유 입력──▶ 위기 규칙(자해/타해/학대)
        │                                                     │걸림
        ▼                                                     ▼
 [② 바꿀 수 있는 일인가]                          [분류별 고정 문구 + 연결처 창]
        ▼                                          + 본인 계정 위기 기록 / 운영자엔 신원 없는 건수
 [③ 선배들은: 태그로 고른 이야기 원문 + 출처 칩]     + 다음 날 앱 안 안부 카드(푸시 없음)
        ▼
 [④ 이번 주 작은 일 고르기(예: 걷기)] ──▶ 작은 일 한 줄 저장(암호화, 계속) / 자유 입력 원문 14일
        ▼
 [다음 주 첫 화면: "지난주 ○○ 해보셨어요?"]
 끄기 스위치 ON → 모든 진입점 "잠시 쉬어요 + 109"
```

## Implementation Tasks
Synthesized from this review's findings. 체크박스로 진행 표시.

- [ ] **T1 (P1, human: 2~3주 / CC: ~30분 양식)** — 사람 — 선배 보호자 인터뷰 + 이야기 동의 (`senior-caregiver-interviews`)
- [ ] **T2 (P1, human: ~1일 / CC: ~30분)** — 문서 — 법률 검토 요청에 도우미 절 추가 (`legal-review-mentor`)
- [ ] **T3 (P1, human: ~1시간)** — 운영 — Gemini 학습 미사용 조건 확인 (`gemini-no-training-check`)
- [ ] **T4 (P1, human: ~1주 / CC: ~2시간)** — ai/backend — 위기 3분류 평가 세트 + 홀드아웃 측정 (`crisis-eval-set`)
- [ ] **T5 (P2, human: ~1일 / CC: ~1시간)** — ai-service — 공유 `gemini_client` 오류 분리 (`gemini-client-error-split`)
- [ ] **T6 (P1, human: ~1일 / CC: ~1시간)** — backend — 이야기 저장소(원문·출처 라벨·상황 태그) 테이블·마이그레이션, 공개 저장소 밖 적재
- [ ] **T7 (P1, human: ~3일 / CC: ~3시간)** — frontend — 카드 흐름 4단계 화면 + 출처 칩 + 화면 이탈 시 비우기
- [ ] **T8 (P1, human: ~2일 / CC: ~2시간)** — backend — 위기 규칙 3분류 + 분류별 고정 문구·연결처 창, AI 호출 없음
