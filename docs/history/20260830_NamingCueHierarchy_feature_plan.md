# 이름대기 단서 위계 (E18) — Feature Plan

- 상태: **초안 — 구현 전 승인 필요**
- 관련: TODOS `E18` `P2`, `E1`(이름대기 비레벨화), `#76`(세션 내 적응)
- 작성 근거: 아래 "현재 코드" 절의 사실은 전부 코드에서 확인한 것이다

---

## 0. 배경 및 문제

이름대기(그림 보고 말하기)는 **7개 하위검사 중 유일하게 난이도 축이 없다.**

E1에서 길이 축을 검토했다가 접었다. 자극 91개의 음절 분포가 1:13 / 2:49 /
3:27 / **4:2**라 4음절 밴드에 자극이 둘뿐이다. 5단계를 만들 수 없다.

임상 표준 축은 길이가 아니라 **단서 위계(cueing hierarchy)** 다. 실어증
이름대기에서 재는 값은 "맞혔나"가 아니라 **"얼마나 도와야 맞혔나"** 이고,
그 도움의 양이 그대로 난이도 단계가 된다. 자극을 하나도 안 만들어도 된다.

### 지금 무엇이 문제인가

현재 화면에는 도움이 **두 단계뿐**이다 — 아무 도움 없음, 또는 `넘어가기`.

```
그림 표시 → 🎤 말하기 → 발음 평가 채점
                  └─ 막히면 [넘어가기] → 목표어 제출 → 정답 처리(assisted)
```

그 사이가 비어 있다. 첫 음절만 들려주면 말할 수 있는 환자와 아무리 해도 못
말하는 환자가 **같은 기록**을 남긴다. 둘 다 `assisted: true`다.

그리고 `assisted` 문항은 **모든 집계에서 빠진다**(정답률, 적응). 그래서 단서를
매번 받아야 하는 환자는 **데이터가 0**이다. 회복 중이어도 화면에 아무것도
나타나지 않는다.

## 1. 개요 및 범위

### 1-1. Deliverable

1. 단서 5단계를 화면에서 순서대로 제공한다.
2. **몇 단계까지 갔는지**를 기록한다(`cue_level`).
3. 보호자 화면이 "정답률" 대신 **필요했던 단서의 양**으로 이름대기를 보여준다.
4. 이름대기가 `presentedLevel`을 갖게 되어 다른 검사와 같은 모양이 된다.

### 1-2. 범위 밖

- **새 자극 제작 없음.** 단서는 기존 `targetWord`에서 만든다.
- 의미 단서 문구의 LLM 생성. 1차는 고정 문구(아래 3-2).
- 이름대기를 세션 내 적응(#76)에 넣는 것 — 별도 판단이 필요하다(6-2).

## 3. 결정이 필요한 지점

### 3-1. ⚠️ "모델 제공"은 현재 설계와 정면으로 충돌한다

`PictureNamingItem.tsx` 머리에 이렇게 적혀 있다.

> 정답을 들려주면 과제가 무의미해지므로 TTS 발음 단서는 제공하지 않는다.

그런데 TODOS의 E18 위계 1단계가 **모델 제공**이다. 그대로 넣으면 이 규칙을 깬다.

**제안: 깨지 않는다.** 모델 제공은 위계에서 빼고 `넘어가기`가 그 자리를 유지한다.
근거는 두 가지다.

1. 모델을 들려준 뒤의 발화는 **이름대기가 아니라 따라말하기**다. 그 과제는
   `repeat`으로 이미 있고 로테이션에 들어간다. 같은 것을 두 검사에서 재면
   보호자 화면의 두 줄이 같은 값을 다르게 부르게 된다.
2. 지금의 `넘어가기`가 이미 "정답을 알려주고 통과"라 모델 제공과 같은 자리다.
   이름만 다르다.

→ **위계는 4단계 + 통과**로 간다.

### 3-2. 단서 사다리 (제안)

약한 것부터 준다. 환자가 다음 단계를 **직접 요청**한다(3-3).

| 단계 | 이름 | 화면에 나오는 것 | 만드는 법 | 못 만드는 자극 |
|---|---|---|---|---|
| 0 | 무단서 | 그림만 | — | 0 |
| 1 | 의미 단서 | "**부엌**에서 쓰는 물건이에요" | `WORD_CATEGORY[slug]` + 한국어 라벨 맵 | **9** |
| 2 | 문장 완성 | "밥을 먹을 때 쓰는 ○○" | 자극별 고정 문구 | **91 (전부)** |
| 3 | 첫 음절 | "**저**…" (자막 + TTS) | `targetWord[0]` | **13** |
| 4 | 통과 | 정답 표시 + 다음 | `targetWord` | 0 |

**"못 만드는 자극"은 전부 실측이다.** 아래 세 절이 각각을 다룬다.

#### ⚠️ (i) 1단계 — `category`가 이름대기 문항에 실려 있지 않다

`QabNamingItem`에는 `category`가 **없다.** `toNamingItem`이 안 넣는다.
값 자체는 `WORD_CATEGORY`(slug 키, export됨)에 있고 `toNamingItem`이 이미
`slug`를 구하므로 **배선은 한 줄**이다. 추가로 필요한 것은 한국어 라벨 맵
15개다(`animal`→동물, `kitchen`→부엌 …).

그리고 **9개 자극은 범주가 `null`이다** — 가방·풍선·바구니·양초·우체통·돌·
우산·열쇠·시계. 이들은 1단계를 건너뛰고 0 → 3으로 간다. 사다리가 자극마다
달라지지만 이건 3-2(c)의 "비교 불가" 문제와 다르다. **결측이 어느 자극인지
고정이고 알려져 있어** 집계에서 보정할 수 있다.

#### ⚠️ (ii) 3단계 — 한 글자 낱말에서 첫 음절 = 정답 전체

**13개가 한 글자다** — 책·꽃·칼·돌·배·곰·집·손·발·눈·귀·코·입. 풀의 14%다.
이들에게 "첫 음절"을 주면 정답을 통째로 준 것이라 3단계와 4단계(통과)가
같아진다. 사다리가 꼭대기에서 무너진다.

**제안: 한 글자 낱말은 첫 음절 대신 초성만 준다.** 책 → "ㅊ…". 임상의
음소 단서(phonemic cue)가 원래 초성이라 오히려 표준에 가깝다. TTS로는
초성을 자연스럽게 못 읽으므로 **이 단계는 자막만** 하고, 대신 "첫소리는
ㅊ이에요"처럼 문장으로 감싸 읽어 준다.

돌은 한 글자이면서 범주도 없어 **사다리가 0 → 4뿐**이다. 유일한 자극이라
1차에서는 그대로 둔다.

#### ⚠️ (iii) 2단계 — 문장 완성은 데이터가 아예 없다

문구는 자동 생성이 안 된다. 91개 자극에 한 줄씩 써야 한다. 세 갈래:

- **(a) 2단계를 1차에서 빼고 3단계로 간다** — 0/의미/첫음절/통과. 데이터 0.
- **(b) 91줄을 쓴다** — 한 번에 다 쓰면 사다리가 완성되지만 작업이 붙는다.
- **(c) 문구가 있는 자극만 2단계를 준다** — 자극마다 사다리가 달라져
  `cue_level`이 자극 간 비교 불가능해진다. **권장하지 않는다.**

→ **(a)로 시작하고 (b)를 후속으로 둘 것을 권한다.** 3단계로도 지금의
2단계보다 훨씬 잘 갈린다.

### 3-3. 누가 단서를 주나 — 환자 self-serve

`💡 힌트` 버튼을 환자가 누른다. 보호자 판단에 맡기지 않는다.

- 이름대기는 **환자 혼자** 하는 경우가 있다(보호자는 회고 화면 쪽이 주 사용처).
- 보호자가 주면 사람마다 기준이 달라 `cue_level`이 사람을 재게 된다.
- 버튼을 누른 것 자체가 "막혔다"는 신호라 측정에 필요한 값이다.

### 3-4. 단서받은 정답을 어떻게 셈하나

**현행 `assisted`의 전부-아니면-전무를 바꾼다.**

- `cue_level = 0`인 정답만 **정답률**에 들어간다 (현행과 동일 — 값이 뜻을 유지한다)
- 그 외 정답은 정답률에서 빠지되 **`cue_level` 자체가 기록되고 그려진다**
- 즉 데이터가 0이 되는 환자가 없어진다. 4→3→1로 내려온 것이 곧 회복이다

## 4. 데이터 모델 변경

### 4-1. `qab_results`

```sql
ALTER TABLE "qab_results" ADD COLUMN "cue_level" SMALLINT;
```

- `NULL` = 단서 개념이 없는 하위검사(이름대기 외 전부), 그리고 이 기능 이전의 기록
- `0` = 무단서 정답
- `1..3` = 그 단계까지 받고 정답
- `4` = 통과(정답을 알려줌)

`assisted`는 **남긴다.** `cue_level >= 1`이면 `assisted = true`로 함께 쓴다.
기존 통계 쿼리 3곳(`quiz.service.ts:1364,1479,1547`)이 그대로 동작해야
마이그레이션이 무해하다.

### 4-2. 이전 기록

`cue_level IS NULL`인 과거 이름대기 기록은 그래프에서 **뺀다**. `assisted`
불리언만으로는 몇 단계였는지 복원할 수 없다. 없는 값을 0으로 채우면
"예전엔 단서 없이 다 맞혔다"는 거짓 회복 곡선이 그려진다.

## 5. 프론트 설계

### 5-1. `PictureNamingItem`

- `cueLevel` 상태(0부터), `💡 힌트` 버튼으로 증가
- 단계별 단서를 **누적 표시**한다(1단계를 받고 2단계로 가면 둘 다 보인다).
  지우면 환자가 방금 들은 것을 기억해야 해서 작업기억 과제가 섞인다
- 3단계 첫 음절은 자막 + TTS 둘 다. 자막만이면 읽기 능력이 섞인다
- `onSubmit(transcript, azure, cueLevel)`로 단계를 함께 올린다
- 기존 `넘어가기`는 4단계로 이름만 바꿔 유지

### 5-2. 도메인 규칙 — `namingCue.ts` (신규)

```ts
export const MAX_CUE_LEVEL = 4;
export function cueForLevel(word: string, category: string | null, level: number): Cue | null;
```

순수 함수로 뺀다. 화면 없이 검증할 수 있어야 한다(`startDestination.ts`,
`sessionAdaptation.ts`와 같은 자리).

### 5-3. 보호자 화면

이름대기 줄만 **정답률 막대 대신 단서 막대**로 그린다.

```
이름대기   ▓▓▓▓▓▓░░░░  평균 단서 1.4단계  (지난주 2.1)
```

DR3에서 정한 규칙을 그대로 따른다 — **표본이 작으면 막대를 그리지 않는다.**

## 6. 미해결

### 6-1. `presentedLevel`을 무엇으로 찍나

`cue_level`은 **결과**지 제시 조건이 아니다. 문항을 낼 때는 아직 모른다.
두 안:

- **(가)** 이름대기는 계속 `presentedLevel`을 안 찍고, `cue_level`만 축으로 쓴다
- **(나)** 직전 세션의 평균 `cue_level`로 다음 세션의 `presentedLevel`을 정하고,
  그 레벨이 **자극 선택**(친숙도/빈도)을 바꾼다 — 단 지금 풀에 빈도 태그가 없다

→ **(가)를 권한다.** (나)는 자극 메타데이터가 먼저 필요하다.

### 6-2. 세션 내 적응(#76)에 넣을 것인가

넣지 않기를 권한다. #76은 정오 이진 신호를 쓰는데 이름대기의 신호는
**연속값(단서량)** 이다. 이진으로 접으면 "단서 3단계 정답"과 "무단서 정답"이
같아져 이 기능이 만든 정보가 그 자리에서 사라진다.

### 6-3. 문장 완성 문구 91줄 (3-2의 b안)

후속 작업. 쓰기로 하면 `namingCues.json`에 자극 slug별 한 줄로 둔다.
