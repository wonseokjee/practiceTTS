# 개발 순서

[개념자료](README.md) 8장을 바탕으로 한 실제 구축 순서입니다.
기간은 소규모 팀(2~4명) 기준의 대략적인 감각이며, 데이터 상태에 따라 크게 달라집니다.

## 순서를 정하는 원칙

**하나. 측정을 가장 먼저 만든다.**
이 도메인은 평균이 거짓말을 합니다(8장). 심도별로 쪼개 볼 수 없는 상태에서
모델을 만들면, 좋아지는지 나빠지는지 모른 채 몇 달을 씁니다.

**둘. 제품 설계를 결정하는 실험을 먼저 한다.**
"화자당 몇 분이면 충분한가"(5장)를 모르면 등록 절차를 설계할 수 없고, 등록
절차가 바뀌면 제품 전체가 뒤집힙니다.

**셋. 쉬운 제품을 먼저 만들어 데이터를 모은다.**
훈련·측정 모드는 기술적으로 쉬우면서(2장) 동시에 **개인 발화 데이터 수집기**가
됩니다. 그 데이터가 소통 모드의 개인화 재료입니다. 순서에 이 인과가 있습니다.

**넷. 언어 층을 음향 층보다 먼저 붙인다.**
어휘 제약과 개인 어휘 등록은 학습 없이 즉시 효과가 납니다(6장). 음향 개인화는
데이터가 쌓인 뒤에 합니다.

---

## 0단계 — 측정 기반 구축 (2주)

모델을 건드리기 전에 해야 할 일입니다.

### 데이터 감사

- 화자당 데이터량 분포 — 히스토그램으로 그려본다
- 심도 분포 — 중도·심도 환자 데이터가 얼마나 되는가
- 낭독 / 자유 발화 비율
- 라벨 현황 — 심도, 화자 ID, 실어증 동반 여부, 발병 후 경과
- 녹음 환경 — 실제 사용 환경과의 격차
- **실제로 들어본다** — 최소 100발화. 숫자로 안 보이는 것들이 있다

### 부족한 라벨 보강

없으면 곤란한 순서대로입니다.

1. **심도** — 없으면 평가가 불가능. 전문가 평정이 이상적
2. **실어증 동반 여부** — 없으면 ASR 실패와 언어 실패를 구분 못 함
3. **발병 후 경과 기간** — 회복 단계 반영

### 평가 하네스

```
입력:  모델, 평가셋
출력:  심도별 / 화자별 / 발화유형별 오류율 분해표
```

**화자 단위로 분할합니다.** 같은 화자가 학습셋과 평가셋에 섞이면 모든 숫자가
부풀려집니다. 이걸 잘못 잡으면 이후 몇 달의 실험이 전부 무의미해집니다.

두 종류의 평가셋을 만듭니다.

- **화자 독립셋** — 처음 만난 환자에게 얼마나 되는가
- **화자 적응셋** — 적응용/평가용으로 다시 나눈 것. 개인화 효과 측정용

### 게이트

- 심도별로 최소 5명 이상씩 확보되었는가
- 중도 이상 환자 데이터가 전체의 10% 이상인가
- 자유 발화가 있는가

**중도 데이터가 거의 없다면** 이후 모든 결과가 경도 편향입니다. 데이터 추가
수집을 먼저 하거나, 제품 범위를 경도~중등도로 명시적으로 좁혀야 합니다.

**낭독만 있다면** 소통 모드는 3단계 이후로 밀립니다. 2단계(훈련·측정)부터
시작하는 것이 맞습니다.

---

## 1단계 — 경계 확인 (3주)

### 1-1. 기준선

공개 사전학습 ASR 모델을 그대로 돌려 심도별 오류율을 잽니다. 아무것도 하지
않은 상태의 성적표입니다.

여러 계열을 함께 봅니다. 자기지도 표현학습 계열과 대규모 지도학습 계열의 성격이
다르고(5장), 특히 후자는 **환각 여부를 별도로 확인**해야 합니다. 침묵 구간에
없는 문장을 만들어내는지 반드시 봅니다.

### 1-2. 도메인 적응

보유한 구음장애 데이터 전체로 파인튜닝합니다. 화자 독립 성능이 얼마나 오르는지
확인합니다.

### 1-3. ★ 개인화 곡선 실험

**이 단계에서 가장 중요한 실험입니다.**

```
화자당 적응 데이터를 5분 / 10분 / 20분 / 40분으로 나눠
각각 적응시킨 뒤 오류율을 측정 → 곡선을 그린다
```

이 곡선에서 두 가지를 읽습니다.

- **꺾이는 지점** — 몇 분이면 충분한가. 이것이 등록 절차의 길이가 됩니다
- **심도별 곡선 차이** — 중도 환자는 더 많은 데이터가 필요할 수 있습니다

동시에 확인할 것: 적응 데이터를 **한 세션에 몰아 받은 경우와 여러 날에 나눠
받은 경우**의 차이. 변동성 때문에 후자가 유리할 것으로 예상되지만, 실제
격차를 알아야 등록 절차를 설계할 수 있습니다.

### 게이트

이 단계가 끝나면 다음 질문에 숫자로 답할 수 있어야 합니다.

| 질문 | 왜 필요한가 |
|---|---|
| 어느 심도까지 실용적인가 | 제품 범위 결정 |
| 개인화로 얼마나 오르는가 | 개인화에 투자할 가치 판단 |
| 몇 분의 적응 데이터가 필요한가 | 등록 절차 설계 |
| 환각이 얼마나 발생하는가 | 모델 계열 선택 |

**개인화 이득이 작다면** 이 프로젝트의 전제가 흔들립니다. 데이터 품질이나
적응 방법을 먼저 점검해야 합니다.

**적응에 40분 이상 필요하다면** 등록 장벽이 너무 높습니다. 훈련 모드를 통한
점진적 수집(2단계)에 더 의존하는 설계로 가야 합니다.

---

## 2단계 — 훈련·측정 모드 출시 (6주)

### 왜 이것을 먼저 만드는가

세 가지 이유입니다.

1. **기술적으로 쉽다** — 목표 문장을 알고 있어 인식 문제가 아니라 정렬 문제
2. **임상 파트너를 얻는다** — 재활 현장에서 바로 쓸 수 있어 협력 관계가 생김
3. **★ 데이터 수집기가 된다** — 환자가 훈련할 때마다 개인 발화가 쌓임

세 번째가 핵심입니다. **훈련 모드는 그 자체로 제품이면서, 동시에 4단계 음향
개인화의 원료 공급 장치입니다.** 등록 절차로 30분을 요구하는 대신, 환자가
훈련하는 동안 자연스럽게 모이게 하는 구조입니다.

### 만들 것

**발음 채점**
- 목표 문장과 실제 발화의 강제 정렬
- 음소 단위 정확도 산출
- **문맥·언어모델을 쓰지 않는다** (2장 — 쓰면 채점이 오염됨)

**훈련 콘텐츠**
- 음소 커버리지를 설계한 문장 세트
- 한국어라면 평음/격음/경음 대립과 종성을 반드시 포함
- 난이도 단계 구성

**임상 측정**
- 명료도 지표 산출
- 종단 추적 대시보드
- **버전을 고정한 별도 파이프라인** (2장 — 모델 갱신이 측정을 오염시킴)

**데이터 수집 파이프라인**
- 훈련 발화를 화자별로 축적
- 목표 문장이 정답 라벨이므로 지도 학습에 바로 사용 가능
- 동의 절차와 보존 정책을 여기서 함께 설계

### 게이트

- 임상의가 측정 결과를 신뢰하는가 (전문가 평정과의 상관)
- 환자가 일주일 뒤에도 훈련하는가
- 화자당 데이터가 목표 속도로 쌓이는가

**마지막이 3단계의 전제입니다.** 데이터가 안 쌓이면 개인화를 할 수 없습니다.

---

## 3단계 — 소통 모드 프로토타입 (6주)

여기서부터 어려워집니다. 자유 발화를 열린 어휘로 인식해야 합니다.

**음향 개인화 없이** 먼저 만듭니다. 언어 층과 대화 설계만으로 어디까지 되는지
확인하는 것이 목적입니다.

### 3-1. 대화 설계부터 (7장)

**이것을 먼저 합니다.** 종단 감지를 고치지 않으면 아무리 인식이 좋아도 제품이
동작하지 않습니다.

- **종단 감지 재설계** — 기본 임계값 2~4초, 환자별 조정
- **명시적 종료 신호** — push-to-talk 또는 종료 버튼. 한 손 조작 가능해야 함
- **봇 발화** — 짧게, 천천히, 문장 사이에 쉼
- **무음 타임아웃 제거** 또는 크게 완화

**환자별 쉼 분포를 측정해 개인 임계값을 잡는 로직**을 여기서 만듭니다.
2단계에서 모인 데이터에 이 정보가 들어 있습니다.

### 3-2. 언어 층 (6장)

학습 없이 즉시 효과가 나는 것들부터입니다.

- **N-best 후보 유지** — 1위만 쓰지 않는 구조로 파이프라인 설계
- **어휘 제약** — 대화 상태에 따라 후보 어휘를 좁힘
- **개인 어휘 등록** — 가족 이름, 병원, 복용 약, 관심사. 등록 시 즉시 입력
- **LLM 복원** — 후보 + 문맥 + 환자 프로필 → 의도 추론 + 확신도
- **복원 층 분리** — 의료 정보는 추론하지 않고 사람에게 넘기는 경로

### 3-3. 확인 전략

- 부분 확인 ("물... 까지는 들었어요")
- 폐쇄형으로 단계적 좁히기
- 선택지 화면 폴백
- 2회 실패 시 모달리티 전환, 3회 시 사람 호출
- **실패의 책임을 시스템에 두는 표현**

### 게이트

- 의도 전달 성공률이 실용 수준인가
- 요구 하나당 평균 발화 반복 횟수
- 포기율
- 폴백(화면 선택) 사용 비율

**폴백 사용률이 지나치게 높으면** 음성이 실질적으로 작동하지 않는 것입니다.
음성 인터페이스 자체를 재고하거나, 대상 심도를 좁혀야 합니다.

---

## 4단계 — 음향 개인화 투입 (4주)

2단계에서 데이터가 쌓인 환자부터 적용합니다.

### 만들 것

- **파라미터 효율 개인화** — 공통 모델 + 환자별 작은 조각
- **조각 단위 저장·배포·롤백** — 환자별 모델 버전 관리
- **콜드 스타트 전략** — 신규 환자는 유사 심도·유형 모델에서 출발
- **삭제 경로** — 환자가 요청하면 조각만 삭제하면 되도록 설계

마지막이 중요합니다. **처음부터 화자별로 분리해두면 나중의 삭제 요구가 재학습
없이 처리됩니다.** 설계 결정이 컴플라이언스를 좌우합니다.

### 게이트

- 개인화 전후 오류율 차이가 1단계 곡선의 예측과 일치하는가
- 개인화 모델을 운영할 수 있는가 (배포, 모니터링, 롤백)
- 특정 환자의 모델이 나빠졌을 때 감지되는가

---

## 5단계 — 온라인 갱신과 운영 (4주)

### 만들 것

- **확인된 발화 수집** — 사용자가 "네, 맞아요"로 확인한 결과를 정답으로 축적
- **정정 데이터 수집** — 사용자가 고쳐준 결과
- **주기적 재적응** — 상태 변화(회복/악화)를 따라감
- **편향 방지 경로** — 실패 사례를 사람이 전사해 넣는 통로

마지막이 빠지기 쉽습니다. **잘 알아들은 발화만 학습에 들어가면 모델이 이미
잘하는 것만 더 잘하게 됩니다.**

### 운영 지표 (8장)

- 심도별 / 화자별 오류율 추이
- 의도 전달 성공률, 발화 반복 횟수, 포기율
- **일주일 뒤 지속 사용률** — 가장 중요한 단일 지표

---

## 6단계 — 임상 검증 (12주 이상)

제품이 안정된 뒤에 시작합니다.

- **대조군 설계** — 자연 회복과 구별하려면 필수
- **보호자 부담 측정** — 통역 횟수 감소가 설득력이 큼
- **삶의 질 척도** — 표준화된 도구 사용
- **기관 심의** — 연구 목적이면 필수

**측정 파이프라인은 이 기간 동안 얼려둡니다.** 모델을 바꾸면 종단 비교가 깨집니다.

---

## 전체 흐름

```
0단계  측정 기반          ─┐
1단계  경계 확인           │ 제품 범위와 등록 절차가 여기서 결정됨
                          ─┘
2단계  훈련·측정 모드      ─┐ 첫 제품이자 데이터 수집기
                          ─┘
3단계  소통 모드 (언어 층) ─┐
4단계  음향 개인화          │ 2단계 데이터가 재료
5단계  온라인 갱신         ─┘
6단계  임상 검증
```

## 병렬로 진행할 수 있는 것

- 3단계 대화 설계와 4단계 음향 개인화는 상당 부분 병렬 가능
- 6단계 임상 파트너 확보는 2단계부터 시작해도 됨
- 윤리·동의·보존 정책은 2단계에서 확정해두는 편이 안전

## 순서를 바꿔야 하는 경우

| 상황 | 조정 |
|---|---|
| 낭독 데이터만 있음 | 2단계에 더 오래 머물며 자유 발화 수집 |
| 중도 환자 데이터 부족 | 0단계에서 수집 우선, 또는 범위를 경도~중등도로 명시 |
| 개인화 이득이 작음 | 언어 층(3-2)에 더 투자, 음향 개인화는 후순위 |
| 시장이 소통 보조를 원함 | 2단계를 축소하고 3단계로 빨리 이동 (데이터 수집은 별도 설계 필요) |
| 임상 파트너가 이미 있음 | 2단계와 6단계 준비를 병행 |

마지막 행이 현실적으로 가장 흔한 변수입니다. **임상 파트너가 있으면 데이터
수집과 검증이 동시에 풀리므로, 그쪽 일정에 맞춰 순서를 재배열할 가치가 있습니다.**

## 가장 먼저 답해야 할 세 질문

전체 순서를 요약하면 이 세 질문에 순서대로 답하는 과정입니다.

1. **어디까지 되는가** — 심도별 기준선 (1단계)
2. **몇 분이면 충분한가** — 개인화 곡선 (1단계)
3. **일주일 뒤에도 쓰는가** — 지속 사용률 (2단계 이후 계속)

1번과 2번은 3주면 답할 수 있고, 제품 설계 전체를 결정합니다.
**이 두 실험을 건너뛰고 구현부터 시작하면 나중에 대부분을 다시 만들게 됩니다.**
