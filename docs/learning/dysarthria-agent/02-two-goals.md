# 02. 두 개의 목표

## 같은 데이터, 반대 방향의 제품

구음장애 발화 데이터를 손에 쥐면 두 가지를 만들 수 있습니다.

**소통 보조** — 환자의 말을 최대한 알아듣는 시스템. 환자가 하고 싶은 말이
세상에 전달되게 돕습니다.

**발음 훈련** — 환자의 발음이 얼마나 정확한지 채점하는 시스템. 재활 훈련의
피드백을 제공합니다.

둘 다 정당한 제품이고, 둘 다 필요합니다. 문제는 **이 둘의 목표가 정확히
반대라는 것**입니다.

## 어떻게 반대인가

환자가 "물 주세요"를 말하려다 "무 두에요"에 가깝게 발음했다고 합시다.

```
소통 보조 시스템:   "물 주세요"로 알아들어야 성공
훈련 시스템:        "발음이 부정확합니다"로 판정해야 성공
```

같은 입력에 대해 **정반대의 출력이 정답**입니다.

소통 보조는 최대한 관대해야 합니다. 왜곡을 보정하고, 문맥으로 추론하고, 어떻게든
의도를 건져내야 합니다. 관대할수록 좋은 제품입니다.

훈련은 최대한 엄격해야 합니다. 왜곡을 정확히 잡아내고, 어느 음소가 어떻게
틀렸는지 짚어야 합니다. 관대하면 쓸모없는 제품입니다.

## 섞으면 둘 다 실패한다

이 구별을 놓치고 하나의 시스템으로 만들려 하면 전형적인 실패가 나옵니다.

**소통 보조에 채점을 섞으면** — 환자가 무언가 말할 때마다 "발음이 부정확합니다"를
듣습니다. 소통하려는 매 순간이 평가받는 순간이 됩니다. 환자는 말하기를 피하게
됩니다. 재활 목표와도 정면으로 배치됩니다.

**훈련에 관대한 인식을 섞으면** — 환자가 어떻게 발음하든 "잘하셨어요"가 나옵니다.
피드백이 없으니 훈련이 되지 않습니다. 그리고 환자는 금방 눈치챕니다. "이거 아무거나
말해도 되는 거 아냐?" 신뢰가 무너집니다.

## 그래서 어떻게 하는가

**모드를 명시적으로 분리합니다.** 사용자가 지금 어느 모드에 있는지 알아야 하고,
시스템도 알아야 합니다.

```
[대화 모드]  — 알아듣는다. 채점하지 않는다.
[훈련 모드]  — 채점한다. 관대하지 않다.
```

기술 스택도 갈라집니다.

| | 대화 모드 | 훈련 모드 |
|---|---|---|
| 인식 목표 | 의도 파악 | 음소 단위 정확도 |
| 모델 | 개인화 ASR + 언어 복원 | 강제 정렬 기반 발음 채점 |
| 어휘 | 열려 있음 (자유 발화) | 닫혀 있음 (목표 문장 기지) |
| 문맥 활용 | 최대한 | 사용하지 않음 (문맥이 채점을 오염) |
| 실패 시 | 되묻는다 | 점수를 준다 |

**훈련 모드가 기술적으로 더 쉽습니다.** 목표 문장을 미리 알기 때문입니다. 무엇을
말할지 아는 상태에서 실제 발화가 얼마나 일치하는지 재는 것은, 무엇을 말할지
모르는 상태에서 알아맞히는 것보다 훨씬 쉬운 문제입니다.

그래서 많은 제품이 훈련 모드부터 시작합니다. 합리적인 순서입니다.

## 훈련 모드가 문맥을 쓰면 안 되는 이유

위 표에서 한 줄이 특히 중요합니다. 훈련 모드는 문맥을 사용하면 안 됩니다.

언어 모델의 도움을 받으면 "무 두에요"도 "물 주세요"로 복원됩니다. 인식은
잘 되는데, 그러면 **틀린 발음이 점수에 반영되지 않습니다.** 채점기가 자기가
고쳐놓고 잘했다고 하는 셈입니다.

발음 채점은 **음향 신호만** 보고 판단해야 합니다. 목표 문장과 실제 발화를
정렬해서 각 음소가 얼마나 목표에 가까운지 재는 방식이 쓰이는 이유입니다.

## 세 번째 목표: 측정

사실 하나가 더 있습니다. **임상적 평가**입니다.

- 이 환자의 명료도는 지금 어느 수준인가
- 지난달과 비교해 나아졌는가
- 어떤 음소가 특히 취약한가

훈련 모드와 비슷해 보이지만 목적이 다릅니다. 훈련은 환자에게 피드백을 주는 것이고,
측정은 임상의에게 데이터를 주는 것입니다.

측정에는 다른 요구가 붙습니다.

- **재현성** — 같은 발화는 항상 같은 점수여야 함
- **표준화된 과제** — 임상에서 쓰는 검사 문항과 대응되어야 함
- **종단 비교 가능성** — 모델을 업데이트하면 과거 점수와 비교가 깨짐

마지막이 실무에서 성가십니다. 모델을 개선했더니 환자 점수가 갑자기 올라갔는데,
이게 환자가 나아진 건지 모델이 바뀐 건지 알 수 없습니다. **측정용 모델은 버전을
고정하고 별도로 관리**해야 합니다.

## 세 목표를 나란히 놓으면

| | 소통 보조 | 발음 훈련 | 임상 측정 |
|---|---|---|---|
| 사용자 | 환자·가족 | 환자 | 임상의 |
| 성공 기준 | 의도 전달률 | 훈련 효과 | 측정 타당도 |
| 관대함 | 최대 | 최소 | 일정해야 함 |
| 문맥 활용 | 적극 | 금지 | 금지 |
| 모델 업데이트 | 자유 | 신중 | 버전 고정 |
| 개인화 | 필수 | 신중 (개인화가 채점을 무디게 함) | 금지 |

마지막 줄이 흥미롭습니다. **개인화는 소통에는 축복이고 채점에는 독입니다.**
환자의 왜곡된 발음에 모델을 맞추면 그 발음을 "정상"으로 취급하게 되고,
채점 기준 자체가 환자에게 끌려갑니다.

## 제품 결정으로 옮기면

무엇을 먼저 만들 것인가는 **누가 돈을 내는가**로 갈립니다.

- **병원·재활센터가 산다** → 훈련 + 측정. 임상 근거와 재현성이 중요
- **환자·가족이 산다** → 소통 보조. 당장 오늘 말이 통하는 게 중요
- **보험·공공이 산다** → 측정. 효과 입증이 지불의 조건

기술적 난이도만 보면 훈련부터가 맞지만, 시장이 소통 보조를 원한다면 순서가
달라집니다. **기술 난이도 순서와 시장 순서가 다를 수 있다**는 점을 의식하고
선택해야 합니다.

## 남아 있는 긴장

한 가지 풀리지 않는 문제가 있습니다.

소통 보조를 너무 잘 만들면, 환자가 발음을 개선할 동기가 줄어들 수 있습니다.
어차피 기계가 알아들으니까요. 재활 관점에서는 이게 손해일 수 있습니다.

반대로 시스템이 알아듣지 못하면 환자는 또박또박 말하려 애쓰게 되고, 그 자체가
훈련이 됩니다. 다만 그건 피로하고, 존엄을 해칠 수 있습니다.

**시스템이 환자에게 맞출 것인가, 환자가 시스템에 맞출 것인가.** 정답은 없고,
환자의 회복 단계와 목표에 따라 다릅니다. 급성기에는 소통이 우선이고, 회복기에는
적당한 도전이 치료적일 수 있습니다.

이 선택은 개발자가 아니라 **임상의가 해야 하는 판단**입니다. 제품은 그 선택을
설정으로 열어두는 것이 옳습니다.

---

**한 문장 요약**
소통 보조는 최대한 관대해야 하고 발음 훈련은 최대한 엄격해야 하므로 두 목표는
정반대이며, 하나의 시스템에 섞으면 둘 다 실패한다.
