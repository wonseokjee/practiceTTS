# 06. 인식 이후의 복원

## 음향에서 못 건진 것을 언어에서 건진다

5장까지는 소리를 더 잘 알아듣는 방법이었습니다. 하지만 한계가 분명합니다.
심도가 높으면 음향 정보만으로는 복원 불가능한 지점이 있습니다.

그런데 사람은 알아듣습니다. 가족은 환자의 말을 상당히 잘 이해합니다.
어떻게 하는 걸까요.

**문맥을 씁니다.** 지금이 식사 시간이고, 환자가 컵을 보고 있고, 방금 목이
마르다고 했다면, "무 두에요"는 "물 주세요"입니다. 소리만으로는 절대 알 수
없는 것을 상황이 알려줍니다.

이 장은 그 방법을 시스템에 넣는 이야기입니다.

## 첫째, 후보를 버리지 않는다

가장 중요한 설계 원칙입니다.

일반적인 ASR은 최선의 하나만 내놓습니다. 그런데 구음장애 발화에서는 **1위와
2위의 차이가 크지 않은 경우가 많습니다.** 확신 없이 고른 1위를 정답으로 확정하면
그 뒤에 손쓸 방법이 없습니다.

```
1위: "무 두에요"   0.31
2위: "물 주세요"   0.28   ← 실제 정답
3위: "문 닫아요"   0.19
```

후보 목록(N-best)이나 격자(lattice)를 유지한 채 다음 단계로 넘기면, 언어 정보로
재순위를 매길 기회가 생깁니다.

**변동성이 큰 입력일수록 결정을 늦추는 것이 유리합니다.** 확신할 수 없을 때
확신하지 않는 것이 옳습니다.

## 둘째, 어휘를 좁힌다

이 방법이 가장 확실하고 가장 저평가되어 있습니다.

한국어 전체 어휘 중에서 고르는 것과, 50개 표현 중에서 고르는 것은 완전히 다른
난이도입니다. 후자에서는 발음이 상당히 왜곡되어도 가장 가까운 것을 찾을 수 있습니다.

```
열린 어휘:  수십만 후보 중 선택 → 어렵다
제약 어휘:  "물 / 화장실 / 아파요 / 추워요 / ..." 중 선택 → 훨씬 쉽다
```

문제는 이것이 표현의 자유를 제한한다는 점입니다. 환자가 하고 싶은 말이 목록에
없으면 아예 전달할 수 없습니다.

**절충은 상황에 따라 어휘를 바꾸는 것**입니다.

```
지금 질문이 "식사 하셨어요?"  → 응답 어휘를 긍정/부정/시간 표현으로 좁힘
지금 질문이 "어디가 불편하세요?" → 신체 부위와 증상 어휘로 좁힘
지금 자유 대화 중            → 넓게 열되 개인 자주 쓰는 표현에 가중
```

대화의 흐름이 곧 어휘 제약을 만듭니다. **폐쇄형 질문이 인식 정확도를 직접
올린다**는 뜻이고, 7장의 대화 설계와 여기서 만납니다.

## 셋째, 개인 언어 모델

환자마다 자주 쓰는 표현이 있습니다. 가족 이름, 다니는 병원, 복용 중인 약,
좋아하는 프로그램. 이것들은 일반 언어 모델에서 확률이 낮지만 이 환자에게는
매우 높습니다.

개인별 어휘와 표현 빈도를 축적해 인식 후보 재순위에 반영합니다. 5장의 음향
개인화와 짝을 이루는 **언어 개인화**입니다.

효과가 즉각적이고 구현이 상대적으로 쉬워서, 개인화의 첫 단계로 삼기 좋습니다.
음향 모델 파인튜닝은 데이터와 시간이 필요하지만, 어휘 목록은 등록할 때 바로
받을 수 있습니다.

```
등록 시 입력: 가족 이름, 주 보호자, 자주 가는 곳, 복용 약, 관심사
→ 즉시 인식 정확도 향상
```

## 넷째, 대형 언어 모델로 복원하기

최근 가장 효과가 큰 접근입니다. 깨진 인식 결과를 LLM에게 주고 원래 의도를
추론하게 합니다.

```
입력:
  인식 후보들: ["무 두에요", "물 주세요", "문 닫아요"]
  상황: 저녁 식사 직후, 병실
  환자 정보: 뇌졸중 후 구음장애, 자주 하는 말 목록
  직전 대화: 봇이 "식사 어떠셨어요?"라고 물음

출력:
  추정 의도: 물을 요청함
  확신도: 중간
  확인 필요: 예
```

LLM이 잘하는 일과 정확히 맞아떨어집니다. 불완전한 입력에서 문맥으로 의도를
추론하는 것 말입니다.

몇 가지 실무 요령이 있습니다.

**후보를 전부 준다.** 1위만 주면 LLM도 1위에 갇힙니다. 후보 목록과 점수를
함께 주면 2위를 고를 수 있습니다.

**상황 정보를 최대한 준다.** 시간대, 장소, 직전 대화, 환자 프로필. 사람이
문맥으로 알아듣는 것을 흉내 내려면 그 문맥을 줘야 합니다.

**확신도를 함께 요구한다.** 이게 핵심입니다. LLM은 시키면 그럴듯한 답을 반드시
만들어냅니다. 확신도를 함께 내놓게 하고, 낮으면 확인 절차로 넘겨야 합니다.

**음소 수준 유사도를 알려준다.** "이 환자는 ㅅ이 자주 ㄷ로 실현된다"를 프롬프트에
넣으면 LLM이 그 패턴으로 복원할 수 있습니다. 환자별 오류 패턴을 축적해 프롬프트에
넣는 방식입니다.

## 복원의 위험

LLM 복원은 강력하지만 새로운 위험을 만듭니다.

**그럴듯한 창작.** LLM은 알아들을 수 없는 입력에도 매끄러운 문장을 내놓습니다.
환자가 하지 않은 말이 만들어지고, 자연스러워서 아무도 의심하지 않습니다.

**의료 맥락에서의 치명성.** 통증 부위, 약 복용 여부, 증상 표현이 잘못 복원되면
실제 위해로 이어질 수 있습니다.

```
환자 발화 (불명확)
LLM 복원: "가슴이 답답해요"   ← 실제로는 "가슴이 아파요"였다면?
```

**대리 발화의 윤리.** 시스템이 환자의 말을 "고쳐서" 전달하는 것이 어디까지
허용되는가. 발음을 다듬는 것과 내용을 바꾸는 것의 경계는 어디인가.

## 그래서 복원에는 층을 둔다

위험을 다루는 방식은 **복원의 정도를 상황에 따라 나누는 것**입니다.

| 층 | 무엇을 하는가 | 언제 |
|---|---|---|
| 0층 | 복원 없음. 인식 결과 그대로 | 측정·훈련 모드 |
| 1층 | 어휘·문법 수준 정규화 | 일반 대화 |
| 2층 | 문맥 기반 의도 추론 | 일반 대화, 확신도 높을 때 |
| 3층 | 추론 후 반드시 확인 | 확신도 낮을 때, 중요한 정보 |
| 4층 | 복원하지 않고 사람에게 넘김 | 의료 정보, 안전 관련 |

**4층이 있어야 합니다.** 통증, 약물, 응급 상황 같은 영역에서는 추론하지 말고
"정확히 이해하지 못했습니다. 다시 말씀해 주시거나 화면에서 골라주세요"로
빠지는 것이 옳습니다.

## 확신도를 어떻게 만드는가

앞의 모든 설계가 "확신도가 낮으면 확인한다"에 기대고 있습니다. 그럼 확신도는
어떻게 계산할까요.

단일 지표로는 부족하고, 여러 신호를 합칩니다.

- **음향 모델 점수** — 후보 간 점수 차이가 작으면 불확실
- **후보 간 의미 차이** — 후보들이 의미적으로 크게 다르면 위험
- **문맥 정합성** — 지금 대화 흐름에 맞는가
- **LLM 자기 보고** — 다만 이것만 믿으면 안 됨
- **환자별 기준선** — 이 환자의 평소 인식 품질 대비 어떤가

마지막이 중요합니다. **절대적 기준으로 자르면 중도 환자는 모든 발화가 "불확실"이
됩니다.** 매번 되물으면 대화가 불가능합니다. 환자별로 기준을 조정해야 합니다.

## 음향과 언어의 분업

정리하면 이런 그림입니다.

```
음향 층 (5장)          언어 층 (6장)
─────────────────      ─────────────────
개인 발화 특성 학습  →   개인 어휘·표현 학습
후보 생성            →   후보 재순위
확신도 계산          →   문맥 기반 의도 추론
                        확신도 낮으면 확인 요청
```

**두 층 모두 개인화됩니다.** 그리고 언어 층 개인화가 훨씬 빠르고 싸게 효과를
냅니다. 데이터 수집 없이 등록 정보만으로 시작할 수 있습니다.

그래서 제품 순서로는 **언어 층 개인화 → 음향 층 개인화** 순으로 붙이는 것이
합리적입니다. 즉시 효과가 나는 것부터 하고, 데이터가 쌓이면 음향으로 넘어갑니다.

**한 문장 요약**
음향에서 못 건진 정보는 후보 유지·어휘 제약·개인 언어 모델·LLM 문맥 추론으로
되살릴 수 있으나, 복원은 창작의 위험을 동반하므로 확신도에 따라 층을 나누고
의료 정보는 추론하지 않아야 한다.
