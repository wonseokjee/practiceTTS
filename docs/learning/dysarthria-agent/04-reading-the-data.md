# 04. 데이터를 어떻게 볼 것인가

## 몇 시간인가는 중요한 질문이 아니다

"구음장애 음성 데이터 200시간을 확보했다"는 말은 생각보다 정보가 적습니다.
같은 200시간이라도 구성에 따라 만들 수 있는 것이 완전히 달라집니다.

먼저 물어야 할 것은 총량이 아니라 **어떻게 나뉘어 있는가**입니다.

## 물어야 할 다섯 가지

### 1. 화자당 몇 분인가

이것이 가장 중요합니다.

```
A안: 화자 200명 × 1시간   = 200시간
B안: 화자 20명 × 10시간   = 200시간
```

총량은 같지만 만들 수 있는 것이 다릅니다.

- **A안** — 화자 독립 모델 학습에 유리. 다양성이 크다
- **B안** — 화자 적응 연구에 유리. 개인화 효과를 검증할 수 있다

5장에서 보겠지만 이 분야의 최대 레버는 개인화입니다. 그래서 **화자당 데이터량이
적으면 할 수 있는 일이 크게 줄어듭니다.** 화자당 10분과 60분은 다른 세계입니다.

### 2. 낭독인가 자유 발화인가

대부분의 공개 코퍼스는 **낭독**입니다. 정해진 단어나 문장을 읽게 하고 녹음합니다.

```
낭독:     "물 주세요"를 읽으세요 → 녹음
자유 발화: "오늘 어떠셨어요?" → 자유롭게 대답
```

낭독 데이터의 장점은 명확합니다. 정답 텍스트가 확실하고, 음소 커버리지를 설계할
수 있고, 발음 채점에 바로 쓸 수 있습니다.

문제는 **낭독과 자유 발화가 음향적으로 다르다**는 것입니다. 낭독할 때 사람은
더 또박또박 말합니다. 화면의 글자를 보고 있으니 단어를 찾느라 멈추지도 않습니다.
자유 발화는 더 흐릿하고, 더 자주 끊기고, 되뇌기와 수정이 섞입니다.

**낭독으로 학습한 모델은 자유 발화에서 예상보다 훨씬 못합니다.** 대화형 에이전트를
만든다면 이 격차를 반드시 측정해야 합니다.

낭독 데이터만 있다면 선택지는 두 가지입니다. 자유 발화를 추가 수집하거나,
훈련·측정 모드부터 만들고 대화 모드는 나중으로 미루는 것입니다(2장).

### 3. 어떤 라벨이 붙어 있는가

있으면 좋은 라벨과 없으면 곤란한 라벨이 있습니다.

| 라벨 | 중요도 | 왜 필요한가 |
|---|---|---|
| **전사 텍스트** | 필수 | 없으면 지도 학습 불가 |
| **화자 ID** | 필수 | 개인화, 화자별 평가 |
| **심도** | 매우 높음 | 심도별 성능 분해 (평균은 무의미) |
| 명료도 점수 | 높음 | 심도의 연속값 버전 |
| 구음장애 유형 | 중간 | 유형별 특성 분석 |
| 진단명·병인 | 중간 | 뇌졸중/파킨슨 등 구분 |
| 발병 후 경과 기간 | 높음 | 회복 단계 반영 |
| 녹음 시각·컨디션 | 낮지만 유용 | 변동성 분석 |
| 실어증 동반 여부 | **높음** | 1장 — 문제의 층이 다름 |
| 음소 단위 정렬 | 훈련 모드에 필수 | 발음 채점 |

**심도 라벨이 없으면 지금이라도 붙여야 합니다.** 없으면 성능 평가가 사실상
불가능합니다. 전문가 평정이 이상적이지만, 최소한 자동 명료도 추정치라도 있어야
합니다.

**실어증 동반 여부**도 자주 빠지는 라벨입니다. 이게 없으면 "인식은 됐는데 말이
안 되는" 사례를 ASR 실패로 잘못 분류하게 됩니다.

### 4. 녹음 환경은 어떤가

```
조용한 스튜디오, 고품질 마이크, 16kHz+
    ↓ 격차
병실, 노트북 내장 마이크, 배경 소음
    ↓ 격차
전화, 8kHz, 대역 제한
```

**학습 데이터와 실제 사용 환경의 격차가 클수록 성능이 무너집니다.** 스튜디오
데이터로 학습해서 병실에서 쓰면 실망합니다.

특히 전화 서비스를 만들 계획이라면, 학습 데이터를 전화 대역으로 열화시켜
성능을 미리 확인해야 합니다. 3장에서 말한 이중 손상이 실제로 얼마나 아픈지
숫자로 봐야 합니다.

### 5. 심도 분포는 어떤가

데이터 수집은 대개 협조가 가능한 환자에게 쏠립니다. 중도 환자는 녹음 세션을
견디기 어렵고, 발화 자체가 힘들어 데이터가 적게 모입니다.

```
흔한 분포:  경도 50% / 중등도 35% / 중도 13% / 심도 2%
```

**정작 도움이 가장 필요한 환자의 데이터가 가장 적습니다.** 이 편향을 인지하지
못하면, 모델이 잘 되는 것처럼 보이는데 실제 도움이 필요한 사람에게는 안 되는
상황이 생깁니다.

## 공개 코퍼스

자체 데이터를 보강하거나 사전학습에 쓸 수 있는 것들입니다.

| 코퍼스 | 언어 | 특징 |
|---|---|---|
| **TORGO** | 영어 | 뇌성마비·ALS. 조음 운동 데이터 동반 |
| **UASpeech** | 영어 | 뇌성마비 중심. 단어 단위 낭독, 다중 마이크 |
| **Nemours** | 영어 | 소규모, 문장 낭독 |
| **Speech Accessibility Project** | 영어 | 최근 구축된 대규모 프로젝트. 파킨슨·뇌졸중 등 포함 |
| **EasyCall** | 이탈리아어 | 명령어 중심 |

두 가지를 짚어둘 만합니다.

**하나.** 대부분 영어이고, **뇌성마비·ALS 중심**입니다. 뇌졸중 후 구음장애와는
유형이 다를 수 있습니다(1장의 표 참조). 사전학습 재료로는 유용하지만 그대로
쓸 수는 없습니다.

**둘.** 한국어 구음장애 데이터는 국내 공개 데이터 플랫폼(AI Hub 등)에서 장애인
음성 관련 데이터셋을 확인해볼 수 있습니다. 다만 구성과 라이선스가 계속 바뀌므로
직접 최신 상태를 확인해야 합니다.

## 언어가 다르면 전이가 제한된다

영어 구음장애 데이터로 학습한 것이 한국어에 얼마나 전이될까요.

**음향 수준의 특징은 상당 부분 전이됩니다.** 기식음, 과다비성, 느린 속도,
음도 불안정 같은 것들은 언어에 무관한 조음기관의 문제입니다. 사전학습 단계에서
쓸 만합니다.

**음소·어휘 수준은 전이되지 않습니다.** 한국어에는 영어에 없는 대립이 있습니다.

```
평음 / 격음 / 경음:  ㄱ - ㅋ - ㄲ
                    ㄷ - ㅌ - ㄸ
```

이 삼중 대립은 **기식성(aspiration)과 긴장성(tension)**으로 구별되는데,
구음장애에서 정확히 이 두 가지가 무너집니다. 호흡 조절이 안 되면 기식성이
흐려지고, 근긴장 조절이 안 되면 경음이 평음처럼 됩니다.

**한국어 구음장애 발화에서 평음/격음/경음 구별이 특히 어려운 이유**이고,
영어 데이터로는 이 문제를 배울 수 없습니다. 한국어 데이터가 반드시 필요한
지점입니다.

종성(받침)도 한국어 특유의 문제입니다. 종성은 불파음으로 실현되어 원래도
단서가 적은데, 구음장애에서는 아예 탈락하는 경우가 많습니다.

## 데이터를 나누는 법

평가를 설계할 때 반드시 지켜야 할 원칙이 있습니다.

**화자 단위로 나눕니다.** 같은 화자의 발화가 학습셋과 평가셋에 나뉘어 들어가면,
모델이 그 화자에 이미 적응한 상태로 평가받게 됩니다. 실제 성능보다 훨씬 좋게
나옵니다.

```
잘못:  전체 발화를 섞어서 8:1:1 분할
올바름: 화자를 8:1:1로 나눈 뒤 발화를 배정
```

다만 개인화 성능을 평가할 때는 의도적으로 다르게 나눕니다.

```
평가 대상 화자의 발화를:
  적응용 (10분) / 평가용 (나머지)
로 나누고, 적응 전후 성능을 비교
```

**두 가지 평가를 모두 해야 합니다.** 화자 독립 성능(처음 만난 환자에게 얼마나
되는가)과 화자 적응 성능(개인화 후 얼마나 되는가)은 다른 질문이고, 제품에서
둘 다 필요합니다.

## 데이터에서 먼저 봐야 할 것

모델을 학습시키기 전에 데이터 자체를 들여다보는 시간이 필요합니다.

- 화자별 데이터량 분포 — 극단적으로 치우친 화자가 있는가
- 심도별 분포 — 중도 환자 데이터가 충분한가
- 발화 길이 분포 — 단어 단위인가 문장 단위인가
- 침묵 비율 — 발화 중 쉼이 얼마나 되는가 (7장 설계에 직결)
- 실제로 들어보기 — 숫자로 안 보이는 것들이 있다

마지막이 의외로 중요합니다. **실제 녹음을 들어보지 않고 만든 시스템은 대개
현장에서 무너집니다.** 기침, 침 삼키는 소리, 보호자의 개입, 중간에 포기하는
발화 같은 것들이 데이터에 섞여 있습니다.

---

**한 문장 요약**
총 시간보다 화자당 데이터량·발화 유형·라벨 구성·심도 분포가 중요하며, 평가는
반드시 화자 단위로 분리하고, 한국어의 평음·격음·경음 대립은 영어 데이터로
대체할 수 없다.
