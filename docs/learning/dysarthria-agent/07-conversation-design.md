# 07. 알아듣지 못할 때의 대화 설계

## 인식률로는 도달할 수 없는 지점

5장과 6장의 방법을 다 써도 중도 환자에게서 오류가 상당히 남습니다. 그리고
남을 것입니다. 완벽한 인식은 이 분야의 목표가 될 수 없습니다.

그래서 제품의 성패는 다른 곳에서 갈립니다. **못 알아들었을 때 무엇을 하는가.**

이 장은 앞 책([../voice-agent-book/](../voice-agent-book/README.md))의 대화 설계가
가장 크게 뒤집히는 부분입니다.

## 뒤집히는 것 하나: 종단 감지

앞 책 7장에서는 침묵 500ms 정도를 기준으로 발화 종료를 판정한다고 했습니다.
여기서는 **재앙**입니다.

구음장애 환자는 호흡 조절이 어려워 문장 중간에 자주 멈춥니다(3장).

```
"물 [1.8초] 좀 [2.2초] 주세요"
```

500ms 기준이면 이 발화는 세 조각으로 쪼개지고, 봇은 "물"만 듣고 반응합니다.
환자는 말을 끊기고, 다시 시작하고, 또 끊깁니다. **이것만으로 제품이 쓸 수
없게 됩니다.**

### 어떻게 바꾸는가

**기본 임계값을 훨씬 길게 잡습니다.** 정상 대화가 500ms라면 여기서는 2~4초가
출발점입니다. 심도가 높을수록 더 깁니다.

**환자별로 조정합니다.** 이 환자의 평소 발화 중 쉼 분포를 측정해 개인 임계값을
잡습니다. 개인화가 여기서도 작동합니다.

**문법적 완결성을 함께 봅니다.** 앞 책 7장의 semantic endpointing이 여기서
더 중요해집니다. 침묵 길이를 신뢰할 수 없으니 다른 신호에 더 의존해야 합니다.
다만 인식 자체가 부정확하므로 이 판단도 흔들립니다.

**명시적 종료 신호를 제공합니다.** 가장 확실한 방법입니다.

```
버튼을 누르고 있는 동안만 듣기 (push-to-talk)
말이 끝나면 버튼 누르기
"끝" 같은 종료 어휘
```

기술적 판정을 포기하고 사용자에게 통제권을 주는 것입니다. 우아하지는 않지만
**중도 환자에게는 이것이 가장 잘 작동하는 경우가 많습니다.** 판정 실패로 인한
좌절이 버튼 조작의 번거로움보다 훨씬 크기 때문입니다.

다만 손 기능도 손상된 환자에게는 이 선택지가 없습니다. 편마비 환자가 많다는
점을 고려해 한 손으로 조작 가능해야 합니다.

## 뒤집히는 것 둘: 끼어들기

앞 책 8장에서는 사용자가 봇의 말을 끊는 상황이 핵심이었습니다.

여기서는 반대입니다. **환자가 끼어들기 어렵습니다.** 발화를 시작하는 데
시간이 걸리고, 목소리가 작아 감지되지 않고, 봇의 말을 끊을 만큼 빠르게 반응하기
어렵습니다.

설계가 뒤집힙니다.

- **봇이 천천히 말합니다.** 빠른 발화는 인지 부하를 높입니다
- **봇이 짧게 말합니다.** 긴 발화는 끼어들 기회 자체를 줄입니다
- **봇이 문장 사이에 쉽니다.** 끼어들 틈을 의도적으로 만듭니다
- **끼어들기 감지 임계를 낮춥니다.** 작은 소리도 발화로 취급

에코 문제는 오히려 덜 심각합니다. 봇이 조용히 말하고 자주 쉬므로 겹칠 구간이
적습니다.

## 뒤집히는 것 셋: 지연

앞 책 9장에서 800ms를 목표로 했습니다. 여기서는 **지연이 덜 중요합니다.**

환자 자신의 발화가 느리고, 대화 전체의 속도가 느립니다. 봇이 1.5초 뒤에
대답해도 어색하지 않습니다.

이것이 여유를 만듭니다.

```
확보되는 예산으로 할 수 있는 것:
- 더 큰 모델로 인식
- 여러 모델의 결과를 대조
- LLM 복원에 충분한 문맥 제공
- 후보를 여러 개 유지하며 재순위
```

**일반 음성 에이전트에서 포기해야 했던 것들을 여기서는 할 수 있습니다.**
지연 예산이 느슨한 것은 이 도메인의 몇 안 되는 이점입니다.

다만 무한정은 아닙니다. 3초를 넘어가면 환자가 자기 발화가 전달되었는지 불안해집니다.
**처리 중임을 알리는 시각·청각 신호**가 필요합니다.

## 확인 전략: 되묻기의 기술

인식이 불확실할 때 되물어야 합니다. 그런데 **되묻는 방식이 환자 경험을 결정합니다.**

### 나쁜 되묻기

```
봇: "죄송합니다, 잘 못 알아들었어요. 다시 말씀해 주세요."
환자: (같은 말을 반복, 더 힘들게)
봇: "죄송합니다, 잘 못 알아들었어요. 다시 말씀해 주세요."
```

세 가지가 잘못되었습니다.

- **정보를 하나도 안 줍니다.** 무엇을 못 알아들었는지 모르니 환자는 전체를 반복
- **부담이 전부 환자에게 있습니다.** 말하기가 힘든 사람에게 반복을 요구
- **반복될수록 굴욕적입니다.** 자기 말이 통하지 않는다는 경험의 누적

### 좋은 되묻기: 부담을 줄이는 방향

**부분 확인.** 알아들은 것을 말하고 모르는 것만 묻습니다.

```
봇: "물... 까지는 들었어요. 물 드릴까요?"
환자: "응" (한 음절이면 충분)
```

전체를 반복하지 않아도 됩니다. **환자의 발화 부담이 크게 줍니다.**

**폐쇄형으로 좁히기.** 열린 질문을 닫힌 질문으로 바꿉니다.

```
1차 시도 (열림):  "무엇을 도와드릴까요?"
2차 시도 (좁힘):  "물이나 음식 관련일까요, 아니면 다른 건가요?"
3차 시도 (닫힘):  "물 드릴까요? 네, 아니요로 답해주세요"
```

**단계적으로 좁혀갑니다.** 6장에서 본 어휘 제약이 대화 흐름으로 구현되는 셈입니다.
질문이 좁아질수록 인식 난이도가 낮아지므로, 되물을수록 성공 확률이 올라갑니다.

**선택지 제시.** 목소리 대신 다른 채널로 답할 수 있게 합니다.

```
봇: "이 중에 있을까요?"
화면: [물]  [화장실]  [아파요]  [다른 것]
```

**모달리티를 바꾸는 것이 가장 확실한 폴백**입니다. 말이 안 통하면 말을 고집하지
않습니다.

### 상한을 둔다

**같은 것을 세 번 이상 묻지 않습니다.** 앞 책 12장에서 "재시도는 한 번"이라고
했는데, 여기서는 이유가 다릅니다. 비용이 아니라 **환자의 체력과 존엄** 때문입니다.

```
2회 실패 → 선택지 제시 (모달리티 전환)
3회 실패 → 보호자·간병인 호출 또는 자유 메모 남기기
```

포기하는 경로가 반드시 있어야 합니다. 그리고 그 포기가 환자의 실패로 느껴지지
않게 표현해야 합니다.

```
나쁨: "죄송합니다, 이해하지 못했습니다."     ← 환자가 실패한 느낌
좋음: "제가 아직 잘 못 알아듣네요. 다른 방법으로 해볼게요." ← 시스템의 한계
```

**책임의 소재를 시스템에 두는 표현**이 중요합니다. 사소해 보이지만 매일 쓰는
사람에게는 누적됩니다.

## 대화의 주도권

일반 음성 에이전트는 사용자 주도가 좋습니다. "무엇을 도와드릴까요?"로 열고
사용자가 자유롭게 말합니다.

**여기서는 시스템 주도가 유리합니다.** 열린 질문은 어휘가 열려 있어 인식이
어렵습니다. 시스템이 먼저 제안하고 환자가 확인하는 구조가 성공률이 높습니다.

```
사용자 주도: "무엇을 도와드릴까요?"  → 인식 난이도 높음
시스템 주도: "물 드릴까요?"          → 네/아니요만 인식하면 됨
```

다만 이건 **환자의 자율성을 줄입니다.** 시스템이 제안하는 것만 할 수 있게 됩니다.

절충은 **주도권을 심도에 따라 조절**하는 것입니다. 경도 환자에게는 열린 대화를,
중도 환자에게는 시스템 주도를 제공합니다. 그리고 환자가 원하면 언제든 열린
모드로 전환할 수 있어야 합니다.

## 시간 압박을 없앤다

일반 음성 에이전트는 무음이 길어지면 통화를 종료합니다. 여기서는 그러면 안 됩니다.

- **무음 타임아웃을 길게** 또는 아예 두지 않음
- **"천천히 하세요"를 실제로 지킴** — 재촉하는 신호를 주지 않음
- **중단과 재개가 자유로움** — 피로하면 쉬었다 이어갈 수 있게
- **세션 길이 제한** — 오히려 너무 오래 하지 않도록 시스템이 권유

마지막이 역설적입니다. 환자는 피로를 인지하지 못한 채 계속하려 하기도 합니다.
발화 품질이 세션 후반에 떨어지는 것이 감지되면 휴식을 제안하는 것이 도움이 됩니다.

## 누가 대화 상대인가

간과하기 쉬운 점이 있습니다. **환자만 사용자가 아닙니다.**

| 사용자 | 원하는 것 |
|---|---|
| 환자 | 자기 말이 전달되는 것 |
| 보호자·가족 | 환자 상태 파악, 소통 부담 경감 |
| 간병인·간호사 | 빠른 요구 파악, 여러 환자 관리 |
| 언어재활사 | 훈련 진행 상황, 객관적 지표 |
| 의사 | 회복 경과, 임상 판단 근거 |

같은 시스템이 여러 사용자를 상대합니다. **화면과 인터페이스가 각각 달라야
합니다.** 환자용 화면은 크고 단순해야 하고, 임상의용 화면은 정보가 조밀해도
됩니다.

그리고 **보호자가 대화에 개입하는 상황**을 설계해야 합니다. 병실에서는 흔합니다.
보호자가 대신 말하거나, 환자의 말을 통역해줍니다. 시스템이 이걸 방해하지 않아야
하고, 가능하면 활용해야 합니다. 보호자의 통역은 **정답 라벨**이 될 수 있습니다(5장).

## 신뢰를 만드는 작은 것들

매일 쓰는 도구에서는 사소한 것이 누적됩니다.

- **인식 결과를 화면에 보여준다** — 틀렸을 때 즉시 알 수 있음
- **틀린 것을 쉽게 고칠 수 있게 한다** — 정정이 곧 학습 데이터(5장)
- **잘 된 것을 과하게 칭찬하지 않는다** — 성인 환자를 아이 취급하지 않음
- **속도와 목소리를 환자가 고를 수 있게 한다**
- **이전 대화를 기억한다** — 매번 처음부터 설명하지 않아도 되게

세 번째가 특히 중요합니다. 재활 맥락의 제품은 과도하게 격려하는 톤이 되기 쉬운데,
성인 환자에게는 무례하게 느껴질 수 있습니다. **담백한 것이 존중입니다.**

**한 문장 요약**
종단 감지는 길게, 봇은 짧고 천천히, 지연 예산은 느슨하게 가져가고, 되묻기는
부분 확인과 폐쇄형 좁히기와 모달리티 전환으로 환자의 발화 부담을 줄이는 방향으로
설계해야 한다.
