# 05. 화자에게 맞추기

## 이 분야의 최대 레버

구음장애 ASR에서 성능을 가장 크게 끌어올리는 방법은 더 큰 모델도, 더 많은 데이터도
아닙니다. **한 사람에게 맞추는 것**입니다.

이유는 3장에서 이미 나왔습니다. 구음장애의 왜곡은 **개인 안에서는 일관적이지만
개인 사이에서는 제각각**입니다. 손상 부위와 정도가 다르니 왜곡되는 방식도 다릅니다.

```
화자 독립 모델:  모든 환자의 평균적인 왜곡을 배움 → 누구에게도 잘 안 맞음
화자 적응 모델:  이 환자의 왜곡을 배움          → 이 환자에게 잘 맞음
```

보고되는 개선폭은 조건에 따라 크게 다르지만, **소량의 개인 데이터만으로도 오류율이
절반 가까이 떨어지는 경우가 흔합니다.** 특히 심도가 높을수록 개인화의 상대적
이득이 큽니다. 화자 독립 모델이 거의 무의미한 수준이기 때문에 올라갈 여지가
많습니다.

## 학습을 어떤 순서로 쌓을 것인가

혼자서 다 하려 하지 말고, 층을 쌓는다고 생각하면 정리가 됩니다.

```
1층. 대규모 정상 발화로 사전학습된 모델      ← 가져다 씀
2층. 구음장애 발화 전반으로 적응            ← 도메인 적응
3층. 이 환자의 데이터로 개인화              ← 화자 적응
4층. 사용 중 계속 수집해 갱신               ← 온라인 적응
```

각 층에서 필요한 데이터량이 확연히 다릅니다.

| 층 | 필요 데이터 | 누가 하는가 |
|---|---|---|
| 1층 | 수만 시간 (정상 발화) | 이미 공개된 모델 사용 |
| 2층 | 수십~수백 시간 (구음장애) | 우리가 보유한 데이터 |
| 3층 | **수분~수십 분 (개인)** | 환자 등록 시 |
| 4층 | 사용하면서 누적 | 운영 중 |

3층의 숫자가 핵심입니다. **개인화에 필요한 데이터는 놀랍도록 적습니다.**
환자에게 30분 녹음을 요구하는 것은 현실적이지만, 10시간을 요구하는 것은 불가능합니다.
이 분야가 개인화에 기대는 이유이기도 합니다.

## 1층 — 어떤 사전학습 모델을 고를 것인가

자기지도 학습으로 대량의 음성을 학습한 모델들이 출발점이 됩니다. 계열이 크게
둘로 나뉩니다.

**자기지도 표현학습 계열** — 음성의 표현(representation)을 배운 인코더입니다.
그 위에 인식 헤드를 붙여 학습합니다. 구조를 통제하기 쉽고, 표현을 다른 과제
(심도 추정 등)에 재사용할 수 있습니다.

**대규모 지도학습 ASR 계열** — 이미 인식까지 완성된 모델입니다. 바로 쓸 수
있고 성능이 높지만, 내장 언어 모델이 강해서 **환각 문제가 있습니다**(3장).
알아듣기 어려운 구간에서 그럴듯한 문장을 지어냅니다.

구음장애에서는 이 차이가 실질적입니다. 환각은 오인식보다 위험합니다. 결과가
자연스러워서 틀린 줄 모르기 때문입니다. 특히 의료 맥락에서는 치명적일 수 있습니다.

**선택 기준**: 인식 성능만 보면 후자가 유리하지만, 환각 제어와 불확실성 추정이
중요하다면 전자가 다루기 쉽습니다. 둘을 조합해 서로의 결과를 대조하는 방식도
가능합니다.

## 2층 — 구음장애 전반에 적응시키기

보유한 구음장애 데이터 전체로 사전학습 모델을 파인튜닝합니다. 여기서 몇 가지
판단이 필요합니다.

### 심도별 가중을 줄 것인가

데이터는 경도에 쏠려 있는데(4장), 정작 도움이 필요한 건 중도 환자입니다.
그대로 학습하면 모델이 경도에 최적화됩니다.

중도 데이터에 손실 가중치를 더 주거나 오버샘플링하는 방법이 있습니다. 다만
과하면 경도 성능이 희생되므로 균형점을 찾아야 합니다.

### 하나의 모델인가 심도별 모델인가

심도별로 별도 모델을 두면 각각에 최적화할 수 있지만, 어느 모델을 쓸지 판정하는
단계가 필요합니다. 그리고 심도는 시간에 따라 변합니다(1장).

실무적으로는 **하나의 모델 + 심도를 조건으로 입력**하는 방식이 관리하기 쉽습니다.
심도 임베딩을 함께 넣어 모델이 스스로 조절하게 합니다.

### 데이터 증강

데이터가 부족하므로 증강이 중요합니다. 다만 **구음장애 특성을 흉내 내는 방향**
이어야 합니다.

| 증강 | 무엇을 흉내 내는가 |
|---|---|
| 속도·템포 변형 (느리게) | 말속도 저하 |
| 성도 길이 변형 (VTLP) | 화자 간 차이 |
| 포먼트 압축 | 모음 중앙화 |
| 침묵 삽입 | 발화 중 쉼 |
| 잡음·잔향 추가 | 실제 사용 환경 |
| 대역 제한 | 전화 환경 |

**정상 발화를 구음장애처럼 변환해 학습 데이터를 늘리는 접근**도 연구되고 있습니다.
음성 변환 모델로 정상 발화에 구음장애 특성을 입히는 방식입니다. 데이터 부족을
근본적으로 완화할 잠재력이 있지만, 변환이 실제 병리 발화를 얼마나 충실히
재현하는지가 관건입니다. 흉내가 어설프면 모델이 엉뚱한 것을 배웁니다.

### 다중 과제 학습

인식만 시키지 말고 관련 과제를 함께 학습시키면 표현이 좋아지는 경우가 많습니다.

```
공유 인코더
 ├─ 음성 인식 (주 과제)
 ├─ 심도 추정
 ├─ 화자 식별
 └─ 명료도 예측
```

부수적으로 얻는 것도 있습니다. 심도 추정 헤드는 그 자체로 임상 측정에 쓸 수
있고(2장의 세 번째 목표), 회복 추적에도 활용됩니다.

## 3층 — 개인화, 실질적인 승부처

### 파라미터를 전부 바꾸지 않는다

환자 한 명당 모델 전체를 복사해 저장하는 것은 비현실적입니다. 환자가 100명이면
모델이 100개입니다.

**일부 파라미터만 학습하는 방식**을 씁니다. 어댑터 모듈을 끼우거나, 저차원
행렬만 학습하거나, 입력 쪽에 화자 임베딩을 더하는 식입니다. 공통 모델은 하나로
두고 환자별로는 작은 조각만 저장합니다.

```
공통 모델 (수 GB) ─┬─ 환자 A 조각 (수 MB)
                   ├─ 환자 B 조각
                   └─ 환자 C 조각
```

이렇게 하면 저장도 배포도 감당 가능해지고, 공통 모델을 개선했을 때 조각을
다시 학습시키는 것도 상대적으로 가볍습니다.

### 적응 데이터를 어떻게 모을 것인가

환자에게 녹음을 요청해야 하는데, 이 과정 자체가 제품 경험의 일부입니다.

**음소 커버리지를 설계합니다.** 아무 문장이나 읽게 하는 것보다, 적은 문장으로
많은 음소와 음소 결합을 덮도록 설계된 문장 세트가 효율적입니다. 한국어라면
평음/격음/경음 대립과 종성을 반드시 포함해야 합니다(4장).

**분산해서 모읍니다.** 3장에서 본 변동성 때문입니다. 한 세션에 몰아서 30분을
받는 것보다, 10분씩 세 번 다른 날에 받는 편이 더 견고한 적응 데이터가 됩니다.

**부담을 관리합니다.** 구음장애 환자에게 말하기는 체력을 소모하는 일입니다.
세션을 짧게 자르고, 중단·재개가 가능해야 하고, 진행 상황이 보여야 합니다.

### 어떤 순서로 등록시킬 것인가

실무적으로 이런 흐름이 됩니다.

```
1. 화자 독립 모델로 즉시 사용 시작 (성능은 낮지만 당장 씀)
2. 사용 중 발화를 수집
3. 일정량이 모이면 개인화 모델 학습
4. 개인화 모델로 전환
5. 계속 수집하며 주기적으로 갱신
```

**처음부터 30분 녹음을 요구하지 않는 것**이 중요합니다. 등록 장벽이 높으면
시작조차 하지 않습니다. 쓰면서 좋아지는 구조가 낫습니다.

## 4층 — 사용하면서 계속 맞추기

운영 중 수집한 데이터로 개인화 모델을 갱신합니다. 두 가지 이유로 필요합니다.

**하나.** 환자의 상태가 변합니다(1장). 회복하거나, 악화하거나, 약물 반응이
달라집니다. 6개월 전 모델은 낡습니다.

**둘.** 실제 사용 발화가 등록 시 낭독 발화보다 실전에 가깝습니다(4장).

문제는 **정답 텍스트가 없다는 것**입니다. 실사용 발화에는 전사가 없습니다.
몇 가지 우회가 있습니다.

- **확인된 발화만 사용** — 사용자가 "네, 맞아요"로 확인한 인식 결과를 정답으로 간주
- **높은 신뢰도만 사용** — 모델이 확신한 것만 학습에 포함
- **사용자 정정 활용** — 사용자가 고쳐준 결과는 확실한 정답

첫 번째가 실용적입니다. 7장에서 다룰 확인 전략이 대화 품질을 위한 것이면서
동시에 **학습 데이터 수집 장치**가 되는 셈입니다.

다만 함정이 있습니다. **모델이 잘 알아듣는 발화만 학습에 들어가면 편향이
강화됩니다.** 못 알아듣는 발화는 확인을 못 받으니 학습에서 빠지고, 모델은 이미
잘하는 것만 더 잘하게 됩니다. 정기적으로 실패 사례를 사람이 전사해 넣어주는
경로가 필요합니다.

## 개인화가 만드는 새로운 문제들

개인화는 강력하지만 공짜가 아닙니다.

**운영 복잡도** — 환자마다 모델 조각이 있으면 버전 관리, 배포, 롤백이 복잡해집니다.
"환자 A의 모델이 이상해졌다"를 어떻게 감지하고 되돌릴 것인가.

**콜드 스타트** — 새 환자는 개인화 데이터가 없습니다. 그 기간을 어떻게 견딜지
설계해야 합니다. 비슷한 심도·유형 환자의 모델에서 출발하는 방법이 있습니다.

**측정 오염** — 2장에서 말했듯 개인화는 임상 측정과 상충합니다. 측정용 모델은
개인화하지 않고 버전을 고정해야 합니다.

**개인정보** — 개인화 모델은 그 사람의 음성 특성을 담고 있습니다. 모델 자체가
생체정보에 준하는 민감 자산이 됩니다. 8장에서 다룹니다.

## 무엇부터 할 것인가

데이터를 손에 쥔 상태에서 우선순위를 매기면 이렇습니다.

1. **사전학습 모델을 그대로 돌려 기준선을 잡는다** — 심도별로 쪼개서
2. **보유 데이터 전체로 파인튜닝** — 개선폭이 얼마나 되는지 확인
3. **화자 적응 실험** — 화자당 5분 / 15분 / 30분으로 나눠 곡선을 그린다
4. 3의 곡선에서 **"몇 분이면 충분한가"를 찾는다** — 제품 등록 절차가 여기서 결정됨
5. 증강·다중과제 등 추가 기법을 얹는다

**4번이 제품 설계와 직결됩니다.** 곡선이 10분에서 꺾이면 등록 절차를 10분으로
설계할 수 있고, 40분까지 계속 오르면 다른 접근이 필요합니다. 이 숫자를 모르고
제품을 설계하면 나중에 전부 뒤집힙니다.

---

**한 문장 요약**
개인화가 이 분야 최대의 레버이며, 사전학습 → 도메인 적응 → 화자 적응 → 온라인
갱신의 층을 쌓되, 화자당 몇 분이면 충분한지를 실험으로 먼저 찾아야 제품 설계가 선다.
