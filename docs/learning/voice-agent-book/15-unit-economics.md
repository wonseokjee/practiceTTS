# 15. 분당 원가의 산수

## 기술이 되는 것과 남는 장사인 것은 다르다

동작하는 음성 에이전트를 만들었습니다. 그런데 이걸 팔면 돈이 될까요.

이 장의 계산은 어렵지 않습니다. 초등학교 산수입니다. 다만 **해보지 않으면
틀린 방향으로 몇 달을 갈 수 있습니다.**

## 원가를 쪼개면

통화 1분에 드는 비용을 항목별로 나눕니다.

| 항목 | 대략적 범위 (분당) |
|---|---|
| STT (스트리밍 인식) | $0.004 ~ 0.010 |
| LLM (토큰) | 아래 별도 계산 |
| TTS (문자 수 기준) | $0.004 ~ 0.020 |
| 텔레포니 (회선 + 번호) | $0.008 ~ 0.015 |
| 인프라 (서버, TURN, 저장) | $0.002 |
| **합계** | **대략 $0.03 ~ 0.06 / 분** |

숫자 자체보다 **구조**를 보세요. LLM이 전부일 것 같지만 실제로는 네 항목이
비슷하게 나눠 갖습니다. LLM만 최적화해서는 원가가 크게 안 내려갑니다.

## LLM 비용 계산해보기

3분 통화, 12턴이라고 가정합니다.

턴마다 대화 이력이 누적되므로 입력 토큰이 계속 늘어납니다. 평균 1,500토큰으로
잡고, 출력은 짧으니 120토큰으로 잡습니다.

```
입력  12턴 × 1,500 = 18,000 토큰
출력  12턴 ×   120 =  1,440 토큰
```

중급 모델 단가($3 / $15 per 1M)로 계산하면:

```
입력  18,000 / 1,000,000 × $3  = $0.054
출력   1,440 / 1,000,000 × $15 = $0.022
────────────────────────────────────
합계                             $0.076  (약 100원)
```

## 여기서 아낄 수 있는 것

입력이 출력보다 두 배 이상 비싼 게 보입니다. 그리고 입력의 대부분은 **매 턴
반복되는 시스템 프롬프트와 대화 이력**입니다.

**프롬프트 캐싱**이 여기서 크게 작동합니다. 같은 접두부를 반복해서 보낼 때,
그 부분을 캐시에서 읽으면 기본 입력가의 10분의 1 수준으로 떨어집니다.

음성 에이전트는 캐싱 효과가 특히 큽니다. 시스템 프롬프트가 길고(행동 규칙이 많음),
같은 통화 안에서 12번 반복되기 때문입니다.

```
캐싱 없음:  $0.076
캐싱 적용:  $0.03 ~ 0.04  (프롬프트 구성에 따라)
```

절반 이하로 내려갑니다. 통화 만 건이면 월 수십만 원 차이입니다.

## 하지만 비용만으로 모델을 고르면 안 된다

싼 모델로 바꿨더니 응답이 느려지고, 도구 호출을 자주 틀리고, 되묻는 턴이 늘었다고
합시다.

```
모델 A:  턴당 $0.006, 평균 12턴  → $0.072
모델 B:  턴당 $0.003, 평균 18턴  → $0.054   ← 싸 보임
```

그런데 18턴이면 통화가 4분 30초로 길어집니다. 텔레포니 비용이 1.5배가 되고,
STT/TTS도 1.5배가 되고, 무엇보다 **봉쇄율이 떨어집니다.** 사용자가 중간에
짜증내고 상담원을 요구하니까요.

봉쇄율이 5%p 떨어지면 절감액이 통째로 사라집니다. LLM 비용에서 아낀 몇 십원보다
훨씬 큰 손실입니다.

**지연·품질·비용 세 축으로 보는 것**이 이 장의 핵심 교훈입니다. 한 축만 보고
최적화하면 다른 축에서 더 크게 잃습니다.

## 상담원과 비교하기

이제 본론입니다. 봇이 상담원보다 싼가.

```
상담원:  시급 12,000원, 평균 처리 3분 → 건당 600원
봇:      분당 약 65원 × 3분          → 건당 200원
```

건당으로는 봇이 3분의 1입니다. 이기는 것처럼 보입니다.

## 그런데 함정이 있다

**봇은 모든 통화를 받고, 그중 일부만 해결합니다.**

```
월 10,000건, 봉쇄율 30%

봇 비용:   10,000건 × 200원 = 2,000,000원   ← 전부 봇을 거침
절감액:     3,000건 × 600원 = 1,800,000원   ← 30%만 해결
──────────────────────────────────────────
순손익:                        -200,000원   ← 적자
```

**봉쇄율 30%로는 손해입니다.**

봇이 못 푼 7,000건은 봇 비용도 쓰고 상담원 비용도 씁니다. 이중 지출입니다.

## 손익분기 봉쇄율

일반화하면 이렇습니다.

```
손익분기 봉쇄율 = 봇 건당 원가 / 상담원 건당 원가
                = 200원 / 600원
                = 33%
```

**33%를 넘겨야 비로소 남습니다.** 그 아래면 안 하는 게 낫습니다.

이 숫자를 아는 것과 모르는 것의 차이가 큽니다. 파일럿 목표를 40%로 잡을지
60%로 잡을지가 여기서 나오고, 안 되는 프로젝트를 일찍 접을 수 있습니다.

## 손익분기를 낮추는 방법

분자를 줄이거나 분모를 키웁니다.

**분자(봇 원가) 줄이기**
- 프롬프트 캐싱
- 통화 시간 단축 (지연을 줄이면 통화도 짧아짐)
- 필요한 구간에만 큰 모델 사용
- TTS 사전 생성 캐시 (고정 문구는 생성비 0)

**분모(상담원 원가) 키우기 — 즉, 비싼 업무를 대상으로**
- 처리 시간이 긴 문의 유형을 고름
- 야간·주말처럼 인건비가 비싼 시간대
- 숙련 상담원이 필요한 영역은 오히려 피함 (봇이 못 함)

두 번째가 전략적으로 더 중요합니다. **어떤 통화를 봇에게 줄지 고르는 것**이
원가 최적화보다 손익에 크게 기여합니다.

## 절감 말고 다른 각도

14장 끝에서 언급한 것을 여기서 계산해봅니다.

```
식당 A: 영업 준비 중이라 못 받는 전화 하루 10통
        그중 3통이 예약으로 이어졌을 것 (전환율 30%)
        객단가 4만원 × 4인 = 16만원

        하루 3건 × 16만원 = 48만원
        월 25일 영업       = 1,200만원
```

봇 운영비가 월 50만원이라면 비교가 안 됩니다.

**절감 논리와 매출 논리는 설득력이 다릅니다.** 절감은 "사람을 자를 건가"라는
저항을 부르고, 매출은 그런 저항이 없습니다. 같은 시스템인데 프레이밍이 다릅니다.

작은 사업장일수록 매출 논리가, 큰 콜센터일수록 절감 논리가 잘 통합니다.

## 남는 질문

지금까지 계산은 **변동비**만 봤습니다. 통화 한 건당 드는 돈이죠.

빠진 게 있습니다. 구축비, 통합 개발, 프롬프트 튜닝, 운영 인력. 이건 통화량과
무관하게 드는 고정비입니다.

고정비가 있으면 **규모가 작을 때 절대 안 맞습니다.** 월 500건짜리 고객은
변동비로는 남아도 구축비를 회수하지 못합니다.

그래서 이 사업의 구조적 질문이 나옵니다. 고객마다 커스터마이징하는 SI 모델로
갈 것인가, 여러 고객이 같은 것을 쓰는 제품 모델로 갈 것인가. 전자는 큰 고객만
받을 수 있고, 후자는 작은 고객을 많이 받아야 합니다.

이 선택이 파일럿을 어떻게 설계할지까지 결정합니다. 마지막 장입니다.

그 값은 봇 건당 원가를 상담원 건당 원가로 나눈 값이다.
