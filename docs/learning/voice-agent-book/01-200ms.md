# 01. 200밀리초의 규칙

## 사람은 생각보다 빨리 대답한다

대화를 나눌 때 상대의 말이 끝나고 내가 입을 열기까지 얼마나 걸릴까. 언어학자들이
여러 언어권의 실제 대화를 녹음해 재본 결과, 화자 전환 간격의 중앙값은 대략
**200밀리초 안팎**이었습니다. 언어마다 다소 차이는 있지만 놀랍도록 좁은 범위에
몰려 있었습니다.

200밀리초가 얼마나 짧은지 감이 잘 안 옵니다. 참고할 만한 숫자를 놓아보면 이렇습니다.

| 사건 | 걸리는 시간 |
|---|---|
| 눈을 한 번 깜빡임 | 약 300ms |
| 사람이 단어 하나를 계획해서 발음하기 시작 | 최소 600ms |
| 대화에서 화자가 바뀌는 간격 | **약 200ms** |

이상합니다. 단어 하나를 준비하는 데 600밀리초가 걸리는데, 200밀리초 만에 대답이
나온다는 건 물리적으로 불가능합니다. 답은 하나뿐입니다. **사람은 상대의 말이
끝나기를 기다리지 않습니다.** 듣는 동안 이미 상대가 무슨 말을 할지 예측하고, 대답을
미리 준비하고, 말이 끝날 지점을 겨냥해 발화를 시작합니다.

이게 이 책 전체를 관통하는 첫 번째 통찰입니다. 대화는 순차적인 주고받기가 아니라
**겹쳐 있는 예측 게임**입니다.

## 순진한 설계

음성 에이전트를 처음 만들 때 누구나 이런 순서를 떠올립니다.

```
사용자가 말한다 → 다 듣는다 → 이해한다 → 대답을 만든다 → 말한다
```

깔끔하고, 구현하기 쉽고, 완전히 틀렸습니다. 이 구조는 각 단계가 앞 단계의 완료를
기다리기 때문에 지연이 그대로 더해집니다. 대충 계산해보면 이렇습니다.

```
말이 끝났다고 판정        500ms
음성을 텍스트로 변환      300ms
LLM이 답변을 생성        1500ms
텍스트를 음성으로 합성    500ms
─────────────────────────────
합계                    2800ms
```

2.8초. 사람이라면 200밀리초에 대답할 자리에서 거의 3초를 침묵합니다. 그 3초 동안
사용자는 무슨 생각을 할까요. "끊겼나?" "내 말을 못 알아들었나?" 그러다 다시
말을 겁니다. 그런데 그 순간 봇이 드디어 대답을 시작합니다. 두 목소리가 겹칩니다.
사용자는 멈칫하고, 봇은 계속 말하고, 대화는 무너집니다.

전화 통화에서는 이게 더 심각합니다. 얼굴을 볼 수 없으니 상대가 생각 중인지 회선이
끊겼는지 알 방법이 침묵의 길이밖에 없습니다.

## 그래서 실제로는

해법의 방향은 하나입니다. **단계를 겹칩니다.**

사람이 듣는 동안 대답을 준비하듯, 시스템도 사용자가 말하는 중에 인식을 시작하고,
인식 결과가 확정되기 전에 답변 생성을 시작하고, 답변이 다 나오기 전에 음성 합성을
시작합니다.

```
사용자 발화  ████████████
STT            ▓▓▓▓▓▓▓▓▓▓▓▓▓   ← 말하는 중에 이미 인식
LLM                    ▒▒▒▒▒▒▒▒  ← 확정 전에 투기적으로 시작
TTS                       ░░░░░░ ← 첫 문장 나오면 바로 합성
출력                        ♪♪♪♪
```

각 단계를 개별적으로 빠르게 만드는 것보다, **겹치게 만드는 것**이 훨씬 큰 이득을
줍니다. 순차 실행에서 2.8초였던 것이 겹침만으로 1초 아래로 내려갑니다.

물론 공짜는 아닙니다. 확정되지 않은 인식 결과로 답변을 만들기 시작했는데 최종 결과가
다르면 그 작업은 버려야 합니다. 낭비되는 계산과 토큰이 생깁니다. 이 낭비를 감수할
가치가 있는가 — 있습니다. 사용자 경험에서 지연은 다른 모든 것을 압도합니다.

## 남는 질문

겹치기로 얻을 수 있는 이득에는 한계가 있습니다. 아무리 겹쳐도 "말이 끝났다"고
판단하는 시간만큼은 반드시 기다려야 합니다. 그런데 그 판단은 얼마나 걸려야 할까요.

너무 빨리 판단하면 사용자가 생각하느라 잠깐 쉰 것을 끝난 걸로 오해해 말을 끊습니다.
너무 늦게 판단하면 지연이 늘어납니다. 이 딜레마는 7장에서 다룹니다.

그리고 더 근본적인 질문이 남습니다. 사람은 200밀리초에 대답하는데 그건 **예측**을
하기 때문입니다. 기계도 예측할 수 있을까요. 사용자가 말을 마치기 전에 무슨 말을
할지 알 수 있다면 지연은 이론상 0이 됩니다. 이건 아직 열려 있는 문제입니다.

---

**한 문장 요약**
사람의 대화는 순차적 주고받기가 아니라 예측으로 겹쳐진 흐름이고, 음성 에이전트도
단계를 겹치지 않으면 대화처럼 느껴지지 않는다.

3. 인식 결과가 확정되기 전에 답변 생성을 시작하면 무엇을 잃는가?
