# 14. 컨택센터의 언어

## 기술이 좋아도 말이 안 통하면

음성 AI를 파는 상대는 대개 컨택센터를 운영하는 조직입니다. 이 업계는 수십 년
동안 자기 언어와 자기 지표를 쌓아왔습니다.

"저희 봇은 지연이 800ms입니다"라고 말하면 아무 반응이 없습니다. "AHT를 20%
줄일 수 있습니다"라고 말하면 대화가 시작됩니다. 같은 시스템 얘기인데 말이 다릅니다.

이 장은 기술이 아니라 **번역**을 다룹니다.

## 전화 한 통이 처리되는 경로

```
착신
 └─▶ IVR         "예약은 1번, 문의는 2번"
     └─▶ ACD     어느 상담원에게 보낼지 결정
         └─▶ 큐   대기음, 예상 대기시간 안내
             └─▶ 상담원 연결 (+ 스크린 팝)
                 └─▶ ACW  통화 후 메모·분류 작성
```

| 용어 | 뜻 |
|---|---|
| **IVR** | 자동응답. 안내 재생하고 키 입력 받음 |
| **ACD** | 자동 호 분배. 어느 상담원에게 줄지 결정 |
| **스킬 기반 라우팅** | 상담원 역량 태그별로 배정 |
| **스크린 팝** | 연결과 동시에 고객 정보가 상담원 화면에 뜸 |
| **ACW** | 통화 후 후처리 시간 (메모, 분류 입력) |
| **WFM** | 인력 운영·스케줄링 |

**음성 AI는 대개 IVR 자리를 대체하거나 그 앞에 섭니다.** 기존 IVR이 "1번을
누르세요"였다면, AI는 "무엇을 도와드릴까요"로 시작해서 상당 부분을 직접
해결하고, 못 하면 ACD로 넘깁니다.

## 이관에도 종류가 있다

| | 무엇 | 고객 경험 |
|---|---|---|
| **Cold transfer** | 그냥 넘김 | 처음부터 다시 설명해야 함 |
| **Warm transfer** | 상황을 정리해서 함께 넘김 | 이어서 진행됨 |

**AI 에이전트의 진짜 가치는 warm transfer에 있습니다.**

봇이 3분간 대화하며 고객 신원, 문의 유형, 예약 번호, 원하는 변경 사항을 모두
수집했습니다. 이걸 상담원 화면에 띄운 채로 넘기면 상담원은 "8월 3일 예약을
5일로 옮기고 싶으신 거죠?"로 시작합니다.

이게 없으면 봇을 거친 3분이 순수한 낭비이고, 고객은 화가 난 채로 상담원을
만납니다. **"봇이 못 풀어서 짜증나는 경험"과 "봇이 미리 정리해줘서 빠른 경험"을
가르는 건 이 한 가지입니다.**

## 업계가 세는 숫자들

| 지표 | 뜻 | AI 도입 시 |
|---|---|---|
| **AHT** | 평균 처리 시간 (통화 + ACW) | 감소 |
| **FCR** | 첫 통화 해결률 | 증가 |
| **CSAT / NPS** | 고객 만족도 | **유지가 목표** |
| **포기율** | 대기 중 끊은 비율 | 감소 |
| **서비스 레벨** | "20초 내 응답 80%" 같은 목표 | 개선 |
| **점유율(Occupancy)** | 상담원이 실제 응대에 쓴 시간 비율 | 상승 |

그리고 AI 프로젝트의 대표 지표가 하나 더 있습니다.

## 봉쇄율

**Containment rate** — 상담원 연결 없이 봇이 끝낸 통화의 비율입니다.

```
봉쇄율 = 봇이 완결한 통화 수 / 봇이 받은 전체 통화 수
```

이 지표가 대표가 된 이유는 **돈으로 바로 환산되기 때문**입니다.

```
월 10,000건 × 봉쇄율 30% = 3,000건이 상담원을 안 거침
상담원 처리 원가 건당 600원 → 월 180만원 절감
```

제안서에 들어가는 숫자가 여기서 나옵니다.

## 봉쇄율만 보면 안 되는 이유

이 지표에는 함정이 있습니다. **봉쇄율은 조작하기 쉽습니다.**

봇이 "상담원 연결해 드릴까요?"를 안 물어보면 봉쇄율이 올라갑니다. 사용자가
"상담원이요"라고 해도 한 번 더 시도해보자고 붙잡으면 더 올라갑니다.

그리고 CSAT가 무너집니다. 그리고 그 고객은 다시는 전화를 걸지 않습니다.

**항상 봉쇄율과 CSAT를 함께 제시해야 합니다.**

```
나쁨:  "봉쇄율 45% 달성했습니다"
좋음:  "봉쇄율 38%, CSAT는 도입 전 4.2에서 4.1로 유지"
```

두 번째가 낮은 숫자인데도 더 신뢰를 얻습니다. 균형을 안다는 신호이기 때문입니다.
이게 기술만 아는 사람과 도입을 이끌어본 사람의 차이로 읽힙니다.

## 반드시 지켜야 하는 것들

컴플라이언스는 협상 대상이 아닙니다.

| 항목 | 내용 |
|---|---|
| **녹취 고지** | 녹음한다면 사전에 알려야 함. 봇의 첫 발화에 포함 |
| **AI 고지** | "AI 상담원입니다" 고지를 요구하는 규제가 늘고 있음 |
| **개인정보 보호** | 전사·로그에서 민감정보 마스킹, 보존 기간 준수 |
| **아웃바운드 제한** | 수신 거부 목록, 발신 가능 시간대 |
| **상담원 연결 권리** | 요청하면 반드시 연결해야 함 |

마지막 항목이 설계에 직접 영향을 줍니다. 사용자가 "상담원"이라고 말하면 봇은
**논쟁하지 말고 즉시 이관해야** 합니다.

봉쇄율을 올리려고 이걸 막는 순간 컴플라이언스 위반이자 CSAT 파괴입니다. 앞의
"봉쇄율 함정"과 정확히 같은 지점에서 만나는 문제입니다.

## 아웃바운드는 다른 게임이다

인바운드(걸려오는 전화)와 아웃바운드(거는 전화)는 규제 강도가 완전히 다릅니다.

인바운드는 고객이 먼저 연락한 것이므로 상대적으로 자유롭습니다. 아웃바운드는
고객이 원하지 않았을 수 있으므로 훨씬 강하게 규제됩니다. 수신 거부 목록 확인,
발신 가능 시간대, 자동 발신 고지 의무 등이 붙습니다.

**학습과 포트폴리오는 인바운드부터 시작하는 게 안전합니다.** 규제 부담이 낮고,
사용자가 이미 도움을 원하는 상태라 성공 확률도 높습니다.

## 남는 질문

지금까지 AI 도입의 효과를 "상담원을 덜 쓰는 것"으로 계산했습니다. 그런데 이게
유일한 가치일까요.

다른 각도가 있습니다. **지금 놓치고 있는 통화**입니다. 야간과 주말에 걸려온
전화, 대기가 길어 끊긴 전화, 상담원이 없어 받지 못한 전화. 이건 인건비 절감이
아니라 매출 증가입니다.

식당 예약을 예로 들면, 영업 준비 중이라 못 받은 전화가 하루 열 통이라면 그건
비용 문제가 아니라 잃어버린 매출입니다. 이 각도로 제안하면 "사람을 자를 건가"라는
껄끄러운 대화를 피하면서 더 큰 숫자를 말할 수 있습니다.
