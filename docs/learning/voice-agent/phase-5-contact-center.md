# Phase 5 — 컨택센터 / CCaaS (2주)

**목표**: 고객사 미팅에서 대화가 통하게 만든다.

이 단계는 기술이 아니라 **업계 언어**를 배우는 구간입니다. 기술이 아무리 좋아도
"AHT를 몇 % 줄일 수 있나요?"에 답하지 못하면 도입 논의가 진행되지 않습니다.

---

## 5-1. 용어 (3일)

### 호 처리 흐름

```
전화 착신
  └─▶ IVR (자동응답)        "1번 예약, 2번 문의"
      └─▶ ACD (호 분배)      스킬·우선순위로 라우팅 결정
          └─▶ 큐 대기         대기음, 예상 대기시간 안내
              └─▶ 상담원 연결  스크린 팝(고객 정보 자동 표시)
                  └─▶ ACW     통화 후 후처리(메모, 분류)
```

| 용어 | 뜻 | AI 에이전트와의 관계 |
|---|---|---|
| **IVR** | 자동응답 시스템 | AI가 IVR을 대체하거나 그 앞단에 위치 |
| **ACD** | 자동 호 분배 | AI가 못 풀면 여기로 넘김 |
| **스킬 기반 라우팅** | 상담원 역량별 배정 | AI가 인텐트를 판정해 스킬 태그를 붙여줌 |
| **인바운드 / 아웃바운드** | 수신 / 발신 | 아웃바운드는 규제가 훨씬 강함 |
| **캠페인 다이얼러** | 대량 자동 발신 | 프리뷰/프로그레시브/프리딕티브 방식 구분 |
| **Warm transfer** | 상담원에게 상황을 설명한 뒤 연결 | AI → 사람 이관의 정석 |
| **Cold transfer** | 그냥 넘김 | 고객이 처음부터 다시 설명해야 함 |
| **WFM** | 인력 운영·스케줄링 | AI 도입 시 필요 인력 재산정 근거 |
| **스크린 팝** | 통화 시작 시 고객 정보 자동 표시 | AI가 수집한 정보를 함께 전달 |

**Warm transfer가 AI 에이전트의 진짜 가치입니다.** 봇이 3분간 수집한 정보를
상담원 화면에 띄운 채로 넘기면, 고객은 같은 얘기를 두 번 하지 않아도 됩니다.
이게 "봇이 못 풀어서 짜증나는 경험"과 "봇이 미리 정리해줘서 빠른 경험"을 가릅니다.

## 5-2. 지표 — 제안서에 들어가는 숫자 (2일)

| 지표 | 정의 | AI 도입 시 방향 |
|---|---|---|
| **AHT** (평균 처리 시간) | 통화 + 후처리 시간 | 감소 (봇이 사전 정보 수집) |
| **FCR** (첫 통화 해결률) | 재문의 없이 끝난 비율 | 증가 |
| **CSAT / NPS** | 고객 만족도 | 유지가 목표 (떨어지면 실패) |
| **포기율** | 대기 중 끊은 비율 | 감소 (대기 없이 봇이 즉시 응대) |
| **서비스 레벨** | "20초 내 응답 80%" 같은 목표 | 개선 |
| **★ 봉쇄율 (Containment Rate)** | **상담원 연결 없이 봇이 끝낸 통화 비율** | **AI 프로젝트의 대표 지표** |

### 봉쇄율이 중요한 이유

AI 도입 효과를 돈으로 환산하는 가장 직접적인 경로입니다.

```
월 통화 10,000건, 건당 상담원 인건비 2,000원
봉쇄율 30% 달성 → 3,000건 × 2,000원 = 월 600만원 절감
봇 운영비 (Phase 7에서 계산) = 월 150만원
→ 순 절감 450만원 / 월
```

**하지만 봉쇄율만 보면 함정에 빠집니다.** 봇이 억지로 붙잡아 봉쇄율을 올리면
CSAT가 무너집니다. 항상 **봉쇄율 + CSAT를 함께** 제시하세요. 이 균형 감각이
"기술만 아는 사람"과 "도입을 이끌어 본 사람"을 가릅니다.

## 5-3. 플랫폼 실습 — 하나만 깊게 (5일)

### 추천: Amazon Connect

무료 티어가 있고 Contact Flow(비주얼 플로우 에디터) + Lambda로 실습이 가장 쉽습니다.

```
Contact Flow 구성 예시

[통화 시작]
   ↓
[녹취 고지 재생]  ← 법적 요구사항
   ↓
[Lambda 호출: AI 에이전트]
   ↓
   ├─ 봇이 해결 → [종료]
   ├─ 봇이 실패 → [Set contact attributes: 수집한 정보]
   │                    ↓
   │              [큐로 전달 → 상담원]  ← 스크린 팝에 정보 표시
   └─ 고객이 "상담원" 요청 → 즉시 이관
```

### 다른 선택지

| 플랫폼 | 특징 | 언제 |
|---|---|---|
| **Amazon Connect** | 실습 쉬움, 개발자 친화적 | 학습용 1순위 |
| **Genesys Cloud CX** | 국내 대기업 콜센터 점유율 높음 | 국내 취업 시 이름값 |
| **Twilio Flex** | 개발자 친화적, 커스터마이징 자유 | Phase 4와 연속성 |

## 5-4. 컴플라이언스 (2일)

| 항목 | 내용 |
|---|---|
| **녹취 고지** | 통화 녹음 시 사전 고지 의무. 봇의 첫 발화에 포함 |
| **AI 고지** | "AI 상담원입니다" 고지를 요구하는 규제 흐름 (지역별 상이) |
| **개인정보 마스킹** | 전사 텍스트에서 주민번호·카드번호 자동 마스킹 |
| **보존 기간** | 통화 기록 보존 기간 규정. 초과 시 자동 삭제 |
| **아웃바운드 제한** | 수신 거부 목록, 발신 가능 시간대 |
| **상담원 연결 권리** | "상담원 연결해주세요"에 반드시 응해야 함 |

**마지막 항목이 설계에 직접 영향을 줍니다.** 사용자가 언제든 "상담원"이라고 말하면
봇은 논쟁하지 말고 즉시 이관해야 합니다. 이걸 막으려고 봉쇄율을 올리는 순간
컴플라이언스 위반이자 CSAT 파괴입니다.

---

## 실습 과제

**Amazon Connect Contact Flow + AI 봇 + 상담원 에스컬레이션**

1. Amazon Connect 인스턴스를 만들고 번호를 할당한다
2. Contact Flow를 짠다: 녹취 고지 → AI 응대 → 분기
3. Lambda에서 Phase 3의 에이전트를 호출한다 (또는 Phase 4의 Twilio 데모를 이관 대상으로)
4. **봇이 못 풀면 수집한 정보를 contact attributes에 담아 큐로 넘긴다**
5. 사용자가 "상담원"이라고 말하면 즉시 이관되는 경로를 만든다
6. 통화 10건을 시뮬레이션하고 봉쇄율을 계산한다

**제출물**: 봉쇄율 + 이관된 통화에서 상담원이 받은 정보 스크린샷.

## 자가진단

- [ ] IVR, ACD, 큐, 스킬 라우팅의 관계를 설명할 수 있다
- [ ] warm transfer와 cold transfer의 차이, 그리고 AI에서 warm이 왜 중요한지 안다
- [ ] AHT, FCR, 봉쇄율을 정의할 수 있다
- [ ] 봉쇄율만 보면 안 되는 이유를 설명할 수 있다
- [ ] AI 도입 효과를 원화로 환산해본 적이 있다
- [ ] 컨택센터 플랫폼 하나에서 플로우를 직접 짜봤다
- [ ] "상담원 연결해주세요"에 대한 설계 원칙을 안다
